# 第一阶段执行清单

在香橙派 4 Pro 6GB 上完成离线中文和英文多轮对话。用 USB 麦克风和音箱，按 Enter 开始会话。ESP32-S3 唤醒、移动底盘和整机充电属于后续阶段。

板上的语音链路是 **USB 麦克风 → SenseVoice 转文字 → Qwen 结合上下文回复 → 所选音色合成 → USB 音箱**。笔记本在写卡、传包和操作终端时使用。

## 各环节所需物料

| 环节 | 所需物料 | 通过条件 |

| 供电与启动 | 香橙派 4 Pro 6GB、散热片、固定 5V 的 USB-C 电源，额定 3A 或 4A | SSH 可登录，系统识别为 4 Pro 和 ARM64 Debian 12，家目录所在文件系统剩余至少 6GB。 |
| 无屏连接与传包 | 普通网线、笔记本网口、离线部署包。笔记本没有网口时用 USB 转网口 | TCP 22 可达，SCP 成功，板端安装脚本校验通过并能输出推理程序版本。 |

网线可直连笔记本，也可接路由器。首次联网排障可借 HDMI 显示器或电视、HDMI 线和 USB 键盘。

## 到货后依次执行

1. **写卡并启动。** 用 Rufus 选择 microSD 卡和指定镜像，核对目标卡容量，如询问模式则选 DD。断电时装好散热片、插卡、接网线，再接固定 5V 电源。首次启动会扩展系统分区。
2. **登录并传包。** Windows 网线直连按[部署指南](orangepi-setup.md)配置，先验证 TCP 22 可达，再以 `orangepi` 登录。板端用 `uname -m`、`cat /etc/os-release` 和 `df -h ~` 核对系统和空间。保持 SSH 窗口打开，另开一个 Windows PowerShell，输入刚确认的板端 IP 并传包。

   ```powershell
   $board = 'orangepi@' + (Read-Host '输入香橙派 IP')
   scp 'D:\Apostgraduate\opencode\embed-study\05-projects\desktop-robot\.local\desktop-robot-orangepi4pro.tar' "${board}:~/"
   ```

   SCP 结束后，在 SSH 窗口解包并安装。安装脚本会离线校验、安装依赖并编译推理程序。

   ```bash
   tar -xf ~/desktop-robot-orangepi4pro.tar -C ~
   cd ~/desktop-robot
   bash setup-orangepi.sh
   ```

3. **确认音频。** 接 USB 麦克风和 USB 音箱。运行 `.venv/bin/python robot.py --audio-check`，说一句并听清回放。如果默认设备选错，先用 `--devices` 查编号，再用 `--input-device` 和 `--output-device` 指定，真人试聊沿用同一对设备。
4. **分别跑中文和英文。** 在香橙派的项目目录先跑合成语音基准，再逐条启动真人试聊。每个基准应退出为 0 并生成 15 个回复 WAV。

   ```bash
   set -o pipefail
   .venv/bin/python bench.py --language zh 2>&1 | tee .local/bench-opi.log
   .venv/bin/python bench.py --language en 2>&1 | tee .local/bench-opi-en.log
   .venv/bin/python robot.py --language zh
   .venv/bin/python robot.py --language en
   ```

   每组按一次 Enter，听到提示音后说话。播完可直接追问。中文说“结束对话”，英文说 `End chat`。切换语言前退出当前程序。初始中文音色是 `melo`，英文是 `lessac`。用 `--list-voices` 查可选音色。
5. **记录并断网复测。** 每种语言分别记录 15 轮回复、6 条上下文追问和播报等待时间，目标是至少 12/15 轮切题、至少 5/6 条上下文追问答对，播报等待中位数 ≤5 秒、P90 ≤8 秒。自 v8（句级流式 TTS）起，延迟验收指标改为「首声等待」：日志行里的 `文件输入到首声`，即从送入音频文件到机器人开始播出第一句声音的时间。按[部署指南的断网步骤](orangepi-setup.md#3-上板验收)依次运行两个语言的基准。英文命令加 `--language en`，另存英文日志。分别核对起止网卡状态、15 轮回复和 `bench_exit=0`。

板端安装完成后（llama-server 为板上源码编译），用 `bench-driver.sh` 后台依次跑中英文各 15 轮，均退出码 0、各生成 15 个回复 WAV。输入仍是合成音频。

内容两项达标；播报等待远超中位数 ≤5 秒、P90 ≤8 秒的目标。分环节看：中文瓶颈是 Melo 整段合成 10–31 秒，LLM 生成 5–10 秒；英文 TTS 仅 0.4–5.3 秒，瓶颈是 LLM 生成 9–17 秒（模型回复偏长，常超出提示要求的 1–2 句）。中文上下文 1 条受 ASR 误识别影响（“那盆植物”识别成“阿鹏植物”），回答仍与前文一致。真人试聊和断网复测尚未进行，延迟优化完成前不做最终验收。

### 板型核对（2026-11-11）

设备树为 `xunlong,orangepi-4-pro`，SoC 兼容串 `arm,sun60iw2p1`；`lscpu` 显示 6 个 Cortex-A55 @1.794GHz（cpu0–5）加 2 个 Cortex-A76 @2.002GHz（cpu6–7），与官方 RK3588S 版本不同。默认 `ondemand` 调频，散热触发点 70/90/110°C（`step_wise`）。

### 延迟优化第一轮（2026-11-11，热机状态，数据偏悲观）

连跑 bench 时 CPU 冲到 89.7–92°C，触发 90°C 保护降频，外壳 42.9°C。因此下面三组数字都含降频损失，只用于比较配置优劣，不作为验收依据。日志在板上 `~/desktop-robot/.local/`，已取回本地同名文件。

| 配置 | 退出码 | 轮数 | 中位数 | P90 | 最快 |
|---|---:|---:|---:|---:|---:|
| 中文换 zh-ll 音色，其余同基线 | 0 | 15 | 20.17 秒 | 29.35 秒 | 4.33 秒 |
| 英文 llama-server 绑 2 大核（cpu6–7）、2 线程 | 0 | 15 | 11.93 秒 | 19.23 秒 | 2.49 秒 |
| 英文绑 4 个中核（cpu4–7）、4 线程 | 中途停止 | 8 | 14.81 秒 | 19.14 秒 | 10.12 秒 |

结论：绑大核对英文收益明显（15.96→11.93 秒，且是在降频状态下取得）；换 zh-ll 音色对中文收益有限（22.68→20.17 秒），中文剩余开销主要在整段 TTS 与 LLM 生成长度；绑 4 中核反而更差，已放弃。

第二轮改用「凉机 + 温度哨兵」重测：`thermal-guard.sh` 每 5 秒采样 cpuL/cpuB 温度，超过 85°C 冻结 `bench.py` 与 `llama-server`，降到 75°C 解冻，并记录温度轨迹与 cpu6 各频点占用时间，用来证明测量期间未触发硬件降频。驱动脚本 `bench-driver3.sh` 依次跑英文（绑大核 2 线程）与中文（绑大核 2 线程 + zh-ll 音色）各 15 轮。

结果作废：冻结本身被算进被测延迟，英文凉机中位数 12.91 秒反而比热机 11.93 秒更差；中文跑到第 7 轮哨兵把进程停掉，只有 7/15 轮。结论是 SIGSTOP 方案污染测量，已放弃，改为只记录不干预的 `thermal-log.sh`，防降频改用固定频率上限。

### 延迟优化第二轮（2026-11-11，v2：缩短回复 + 大小核分工 + 大核限频）

改动三处：`max_tokens` 96→48、中英文提示词收紧成一句话；新增 `--tts-threads`，`llama-server` 经 `llama-big.sh` 绑 cpu6–7 跑 2 线程，TTS 单独 6 线程；`opi-thermal-cap.sh` 把大核 policy6 上限设为 1716000，配合被动散热（去外壳、竖放）。
