> 2026-11-12机械路线更新：用户明确采用双履带。[最新整机框架](framework/README.md)与[履带实施规格](framework/tracked_motion.md)为后续入口。本文的双轮、轮组、N20/TB6612及前后两只ToF为早期候选，保留历史，不视为已采购或适用于履带；需重新核对质量、驱动电流、接地/扫掠覆盖和停车距离。

整机采用香橙派 4 Pro 6GB 和 ESP32-S3。香橙派在本机运行中英文语音和车头摄像头的桌沿检测。ESP32-S3 负责离线唤醒、两轮控制、ToF 测距、停机和表情屏。前进须同时通过视觉、测距、串口和实体停机检查。首版用固定语音口令移动，关机后从机身 USB-C 口给电池充电，中英文分别保存音色。约 1500 元为原整机硬件目标，增加摄像头和表情屏后按所选器件重新核算。

现有成果包括电脑端语音程序、系统镜像、语音部署包，以及台架视觉诊断、前进联锁核心和彩色表情素材导出。实板启动、唤醒固件、运动控制、电源和外壳均待按下列顺序完成。 [第一阶段执行清单](phase-1-runbook.md)

## 1. 跑通香橙派离线双语

1. 用 Rufus 把 Debian 12 镜像写入 microSD 卡。贴散热片，插卡、接网线，最后用套装固定 5V 电源上电。首次启动扩容完成后通过 SSH 登录，确认板型、ARM64、Debian 12 和至少 6GB 可用空间。
2. 通过 SCP 上传部署包，解包并运行 `bash setup-orangepi.sh`。脚本核对文件、离线安装依赖并在板上编译 `llama-server`。
3. 插 USB 麦克风和音箱，用 `--devices` 查设备，再用 `--audio-check` 验证指定设备的三秒录音回放。
4. 分别运行 `bench.py --language zh` 和 `bench.py --language en`，然后按题组真人试聊。用 `.local/voices.json` 分别设音色。最后按指南断网复跑并保存日志。

**通过条件**。两种语言各 15 轮均生成回复。真人对话各至少 12/15 轮切题、5/6 条上下文追问答对。说完到开始播报中位数 ≤5 秒、P90 ≤8 秒。查看温度和内存，按最终所选音色计时。 [镜像、部署包和逐条命令](phase-1-runbook.md)

## 2. 跑通 ESP32-S3 唤醒、表情屏与开机自启

目标是断网冷启动后，按当前语言模式唤醒一次就能连续交谈。香橙派上的 USB 麦克风负责整句识别，ESP32-S3 上的 I²S 麦克风负责待机唤醒。这一阶段可在车轮和电池到货前完成。

### 2.1 准备物料和开发环境

| 物料 | 数量 | 核对内容 |
|---|---:|---|
| ESP32-S3 开发板 | 1 | 优先 N16R8。核对板卡丝印、厂家原理图、USB 数据口、Flash 和 PSRAM 规格。 |
| INMP441 I²S 麦克风模块 | 1 | 确认是 3.3V 供电的 I²S 模块，能接出 BCLK、WS、SD 和 L/R。 |
| USB 数据线 | 1 | 先连接笔记本烧录和看日志，再接香橙派做串口通信。 |
| 面包板、跳线、状态 LED 和限流电阻 | 各 1 套 | 可用板载灯验证；灯型和引脚按实买板确定。 |
| 语言切换按钮 | 1 | 台架先用配置选择语言，联调时加实体按键。 |
| ESP-IDF、ESP-SR 和官方唤醒模型 | 各 1 套 | 保存编译器、组件和唤醒模型版本。选同一个官方唤醒词开启中英文模式。 |

### 2.2 先验证麦克风，再刷入唤醒模型

1. 断电接线。模块 VDD 接 3.3V，GND 接地，SCK/BCLK、WS 和 SD 分别接 ESP32 的位时钟、字选和数据输入。L/R 选左槽时接地，程序选择同一声道。按板图避开启动绑带、板载 Flash/PSRAM 和实际用到的 USB 引脚。等板型确定后，把端子名和 GPIO 编号记到接线表。
2. 先运行录音诊断。以 16kHz 采样，按 INMP441 的 I²S 时序接收双 32 位槽中的有效样本，再取所选槽转换为带符号的 16 位单声道 PCM。检查静音、正常说话和轻敲桌面时波形，确认有语音幅度、符号正确、无持续饱和。输入 AFE 时按实际通道配置和帧长喂数据。
3. 加入 ESP-SR，启用相应 PSRAM 和模型分区。首刷用完整构建和烧录步骤写入应用、分区表和模型；启动后核对实际加载的模型名。用笔记本串口日志确认一次唤醒生成一个事件，再接香橙派。 [乐鑫开发板参考](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32s3/esp32-s3-devkitc-1/user_guide_v1.1.html) · [INMP441 数据手册](https://invensense.tdk.com/wp-content/uploads/2015/02/INMP441.pdf) · [WakeNet](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/wake_word_engine/README.html) · [ESP-SR 模型烧录](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/flash_model/README.html)

### 2.3 接入双语对话与串口

1. 在香橙派的 USB 主机口连接 ESP32 数据口。用 `/dev/serial/by-id/` 定位串口；开发板没有唯一标识时，可固定物理 USB 口并用 `/dev/serial/by-path/`。协议帧按行分隔，限定长度，带版本、连接会话号和序号。先实现握手、唤醒、允许或禁止唤醒、状态、心跳、回执；串口重连建立新会话。调试日志单独输出。
2. 香橙派在本地模型、音频设备和串口均就绪后，才通知 ESP32 进入待唤醒。收到唤醒事件后先禁止再次触发，播放提示音，提示音播完才录音；检测到说完后走识别、对话、短句播报。播报期间暂停录音，播完继续听，保留本次会话上下文。
3. 当前轮进入听取后，连续 15 秒无语音，或识别到“结束对话”或 `end chat`，结束会话并清空上下文。设备健康时恢复唤醒。待机时按键切换并保存语言，下一次会话用该语言；会话中固定所选语言。继续用已有的 `.local/voices.json` 分别选择中英文音色。
4. 设置可区分的状态灯，例如待机慢闪、听取常亮、处理快闪、播报双闪；故障单独提示。保留第一阶段的回车入口做人工诊断，另加串口入口给整机服务。
5. 用非 root 的 `systemd` 服务启动整机入口，配置工作目录、模型路径、音频及串口权限，异常退出后限速重启。心跳及串口状态处理与识别、模型推理和播放分开运行。任一设备掉线后退回故障状态，恢复握手且音频重新就绪后才回待机。 [systemd 服务配置](https://www.freedesktop.org/software/systemd/man/252/systemd.service.html)

### 2.4 台架验收

| 项目 | 操作与判据 |
|---|---|
| 唤醒 | 安静桌面做 20 次，至少 18 次成功。记录距离、朝向、说话人、背景噪声和漏唤醒。记录连续 5 分钟日常环境中的误唤醒次数，另测机器人自身播报。 |
| 多轮与音色 | 中英文各用第一阶段题组跑 15 轮。每种语言至少 12 轮切题，6 条上下文追问至少答对 5 条；切换后试听所选音色。一轮播完直接说下一句，整段只需一次唤醒。 |
| 时延 | 从用户说完到首个可听回复，记录中位数和 P90，沿用 ≤5 秒和 ≤8 秒目标。拆记识别、生成和首段合成耗时。 |
| 边界与恢复 | 等待 15 秒退出、用结束口令退出、播放时尝试唤醒、串口重复帧、拔插串口和音频设备。恢复后只开启新会话。 |
| 自启 | 断开网络并关闭笔记本，给香橙派和 ESP32 冷启动。等就绪灯后分别开启中英文会话，保存两端日志。 |

### 2.5 接入表情屏

1. 为 ST7789 彩屏分配硬件 SPI 的 MOSI、SCLK 和 CS、DC、RST、BL GPIO。用稳压 3.3V 供电，与 ToF 的 I²C 信号线分开。先断电接线，再用三色条和四角标记核对色序和竖屏方向。 [彩屏接线与素材](vision-face-runbook.md#4-表情屏素材与固件)
2. 屏幕只显示角色表情。首版使用五套彩色素材，分别对应待机、听取、思考、播报和停机。后续用同一 Q 版人物的 PNG 替换各状态图片。ESP32 根据本地保护状态选择警觉表情，香橙派只发送对话状态。图像诊断在台架日志或采集文件查看。
3. 表情任务读最新状态，低优先级分块刷新，限制待发送队列。刷新等待超时后由显示任务单独处理。架空模拟拔屏和显示超时，同时注入桌沿或实体停机，记录保护延迟。装壳后复测。

### 3.2 先架空接电机和停机

1. 固定左右电机和支撑轮，给车轮留转动空间。ESP32 接驱动模块的方向、PWM 和 STBY 信号。逻辑电源与电机 VM 按模块规格独立接入，保持共同信号参考地，电机回流走自身支路。用硬件下拉保证驱动使能在复位和上电阶段关闭。
2. 实体停机的主触点串入电机 VM 支路，辅助触点以 3.3V 兼容方式接给 ESP32。先测开关通断和 VM 电压，再架空逐个驱动左右轮，记录正转、反转、启动 PWM 和停车表现。定义每轮的前进方向，修正安装镜像造成的极性差异。
3. 分别测驱动的制动状态和实体停机断电后的滑行。实体按钮切掉电机支路后，车轮可能继续滑行，桌沿验收按实际最差距离设计。释放按钮后维持零输出，重新收到有效口令才允许动作。 [TB6612FNG 模式表](https://toshiba.semicon-storage.com/info/datasheet_en_20141001.pdf?did=10660)

### 3.3 校准桌沿传感器

1. 先单只验证测距。接上两只后，用独立 XSHUT 逐只释放并分配唯一 I²C 地址；重启时重做分配。XSHUT 电平以载板说明为准。参考载板的 XSHUT 拉低后以高阻释放，避免向低压引脚直接推送高电平。核对所用驱动 API 的地址表示。
2. 记录前后安装高度、离轮轴的距离和传感器投影点。对计划使用的桌面分别记录静止、行驶震动、不同光照和边缘处的数据。用同一批数据定正常距离范围、桌沿阈值和采样超时。将无效状态、超时和距离越界都视为禁止动作。
3. 前进检查前部，后退检查后部，转向检查前后传感器状态及轮子实际扫过的范围；任一安全相关读数失效时停止。用慢速录像确认从发现边缘到停住的位置。传感器在行进方向上领先危险轮的距离，须大于检测与控制期间的移动距离、最差停车距离及实测余量之和。
4. 先在地面或围挡内从约 3–5 cm/s 试起，实测后设速度上限。若某个方向或桌面材质无法可靠覆盖，禁用对应动作，调整安装点或增配传感器后复测。 [ST 多传感器配置与测距状态](https://www.st.com/resource/en/user_manual/um2931-a-guide-to-using-the-vl53l4cd-ultra-lite-driver-uld-stmicroelectronics.pdf)

### 3.4 接入固定口令

| 动作 | 中文整句 | 英文整句 |
|---|---|---|
| 前进 | 前进 | move forward |
| 后退 | 后退 | move backward |
| 左转 | 左转 | turn left |
| 右转 | 右转 | turn right |
| 停止 | 停止 | stop moving |

1. 复用现有 `robot.py` 的整句匹配，先用模拟输出验收，再接真实串口发送。普通聊天走对话和播报。动作消息使用固定动作码、连接会话号和序号，记录受理或拒绝原因。模型输出仅进入播报通道。
2. ESP32 仅在连接有效、心跳正常、停机未触发、传感器正常时启动车轮。接入视觉后，前进还需新鲜的视觉许可，整个前进过程持续检查。无视觉的早期电机联调限于架空或地面围挡台架。本地计时将每次移动限制在 300 毫秒以内。初调可试 100 毫秒心跳和 250–300 毫秒断链窗口，最终按采样节拍、延迟和实测停车距离定值。
3. 丢弃重复、过期和旧连接的动作。断链、复位、停机、传感器故障均清除待执行动作，恢复后等待新口令。语音停止受拾音和识别延迟影响，紧急停轮用实体开关。

### 3.5 验收顺序和记录

| 顺序 | 测试 | 通过判据 |
|---|---|---|
| 1. 架空 | 上电和重启、左右轮单测、五个口令各 5 次、实体停机后复位 | 转向与标签一致，每条移动最多 300 毫秒；上电静止，复位后无自行续跑。 |
| 2. 围挡内 | 中英文口令、含口令的普通句子、回放重复帧和旧帧、运行中拔串口、模拟主控重启、拔掉 ToF 或制造无效读数 | 只有整句有效口令触发动作；故障时驱动关闭，恢复后须新指令。记录触发到停轮时间。 |
| 3. 系绳桌沿 | 完成 3.6 的视觉联锁后验证前进、后退、斜向和转弯，覆盖实际桌面边角；分别量制动和断电滑行距离 | 轮子在越界前停住并留有实测余量。记录表面材质、光照、速度、测试方向、停车距离及通过次数。 |

### 3.6 接入摄像头和前进联锁

车头镜头朝前下方，香橙派持续分析两轮前进路径。画面中发现桌沿或无法确认前方路面时，拒绝新的前进口令，并中止正在执行的前进。摄像头断开、遮挡、采集超时和进程停滞也会撤销许可。ESP32 独立执行 ToF 和实体停机，前向摄像头的结果仅适用于经标定的前进路径。完整接线、标定、串口许可和故障验收见[视觉与表情屏执行清单](vision-face-runbook.md)。

## 4. 跑通电池、正常关机和机身 USB-C 充电

先沿用台架电源完成第 3 阶段，再按整机负载定电池。最终的供电关系是机身 USB-C 口进入充电管理模块，成品电池包经受保护的负载输出分别给香橙派和电机支路。实体停机独立切断电机支路。

### 4.1 测功耗并选购

1. 用第 1 阶段的 5V 电源给香橙派供电，用独立台架电源给电机支路供电。在主板端和驱动端分别记录电压、电流。依次测待机、识别、模型推理、扬声器播报、摄像头采集与处理、彩屏背光全亮并刷新、单电机启动和双电机启动。再用受控台架把上述高负载工况叠加，记录最低电压、峰值电流、有无音频或摄像头重连、视觉处理延迟或系统重启。用示波器核对功率计可能漏掉的瞬态压降。
2. 用混合工作时两支路平均功率之和估续航。电池标称容量以 Wh 比较，起算值为平均负载功率 × 0.5 小时 ÷ 稳压效率 ÷ 可用容量比例，再留余量。另核对低电量时电池、保护板和稳压器仍能承受实测启动峰值。
3. 选受保护的成品电池包，按厂商确认的串数、充电终止电压、最大充放电电流、温度检测要求、插头和针序匹配管理板。检查整机占位、固定方式及充电口位置。采购前留存两端规格和配套说明。

| 物料 | 数量 | 下单前核对 |
|---|---:|---|
| 带保护的成品电池包 | 1 | 标称 Wh、持续及峰值放电电流、温度条件、尺寸、插头和针序。 |
| 带 USB-C 充电输入的管理板、配套充电器和线 | 各 1 套 | 充电档位、电池兼容、负载开关、充电状态输出、低电量信号以及能否实现充电互锁。 |
| 主控稳压、电机稳压或限流 | 各 1 支路 | 主控为固定 5V，电机支路按所选型号。核对峰值能力、端电压、过流保护和热表现；管理板内置功能可按规格合并。 |
| 关机按钮、负载开关、保护和线材 | 1 套 | 按实际电流选开关、保险或限流、线径、端子。留独立停机和充电互锁。 |
| 万用表、功率计、台架电源 | 各 1 | 可借用。需要捕捉瞬态时加示波器。 |

香橙派 4 Pro 的 Type-C 供电端为固定 5V 输入，无 PD 协商。中文版手册 v1.4 的 PDF 第 15 页推荐 5V/3A，第 40 页也列出 5V/4A 适配器。原计划中的 PiPower 5 使用面向树莓派的接口设计，若考虑继续使用，需逐项验证给香橙派供电的接法、关机信号和两支路峰值。其 Default OFF 设置可避免插入充电线时自动启动；仍需额外验证硬件能在充电中拦住手动开机。 [香橙派 4 Pro 用户手册](https://orangepi.net/wp-content/uploads/2026/01/OrangePi_4_Pro_A733_User-Manual_v1.4.pdf) · [PiPower 5 接口及开关](https://docs.sunfounder.com/projects/pipower5/en/latest/pipower_hat.html)

### 4.2 搭台架电源并验证关机顺序

1. 先搭管理模块、保护件和两支路。给香橙派供电前，用万用表核对电压和极性；两支路的正极分别接入。接上实际负载后，在主板输入端复查压降，并检查接头、稳压器和导线温度。
2. 台架先走人工顺序。停轮并禁止新动作，执行 Linux 的 `poweroff`，按实板的可观测关机状态确认停机，再切断负载电源，最后插机身 USB-C 充电。最终单键版再加入经过验证的关机完成信号与负载开关。把“请求关机”和“系统已停机”作为两个独立状态验证。
3. 做充电互锁。插入充电线后，负载开关保持关闭，操作启动键也无法给香橙派和电机上电；拔线后由用户重新开机。按最终接线检查 ESP32 和各 USB 外设是否存在旁路供电。验证充电指示能从外部看见。复用第 3 阶段的实体停机开关。
4. 接入低电量检测。按电池和管理板规格设预警条件，在保护板切断前先禁用电机并正常关机。先用可控供电或模拟低电量信号验证顺序，再用电池确认；保留实测剩余关机时间。

### 4.3 验收

| 项目 | 操作与判据 |
|---|---|
| 峰值供电 | 复跑摄像头采集处理、彩屏背光全亮并刷新、推理、播报和双轮启动的叠加工况。记录主板最低端电压、各支路峰值及最高温度，检查欠压、摄像头掉帧、USB 音频和串口日志。 |
| 充电循环 | 做 3 次正常关机、插线、观察充电、拔线、重新开机。每次插线后尝试开机，主控和轮子须保持断电；拔线后由开机键启动。 |
| 续航 | 电池供电连续混合运行至少 30 分钟。记录对话与移动次数、电池起止状态、最低端电压、温度和异常；全程无欠压重启、音频断连或保护触发。 |
| 低电量 | 用模拟信号或受控供电触发，验证先停轮、拒绝新动作，再正常关机。记录告警到负载断开的时间。 |

## 5. 打印外壳、整机复测和归档

按实际装配测量做可拆机身。先试底盘，再试装上盖；最终壳体要保留操作、散热、维修和桌沿检测空间。

### 5.1 物料与测量

| 物料 | 数量 | 用途 |
|---|---:|---|
| 3D 打印耗材 | 按试片和整机估料 | 先打印孔位和接口试片，再出底盘与上盖。 |
| 螺丝、螺母或热熔螺母、铜柱或绝缘支柱 | 按实际安装孔 | 可拆装板卡、上盖、音箱和传感器，避免螺丝接触电池或 PCB。 |
| 电池固定架或绑带、扎带、热缩管 | 各 1 套 | 约束电池及线束，给插拔留空间和应力释放。 |
| USB-C 固定件、按钮安装件、传感器支架 | 按实物 | 让充电口、关机键、停机键、指示灯和 ToF 保持可用。 |
| 风扇及导风件 | 按温升决定 | 结合已安装的散热片和开盖、合盖测试选型。 |

1. 用卡尺量香橙派、ESP32、电源板的外廓、安装孔坐标和最高元件；量电池含接头的尺寸、音箱、散热片和风扇高度。选一个底盘原点统一记录尺寸。
2. 量车轮转动包络和支撑轮转向空间，保留可调 ToF 架的行程；记录传感器离桌面高度、到轮子的领先量与向下视野。量 USB、线束和端子的插拔距离及弯折空间。
3. 把电池安排在低位，用托架与绑带固定，远离发热部件、尖角和螺钉末端。试装时检查重心、支撑轮着地和维修拆卸顺序。

### 5.2 打印与装配

1. 先打安装孔、充电口和卡扣小试片，按打印机的实际尺寸偏差修正 CAD。用开放底盘装轮组、板卡和电池，确认离地间隙、走线、整机重心和充电插头空间。 [Prusa 3D 打印建模指南](https://help.prusa3d.com/article/modeling-with-3d-printing-in-mind_164135)
2. 再做可拆上盖。给两只麦克风各留声孔，尽量远离扬声器、风扇和电机。给进风、出风留通道。按实物做正面表情屏压框和独立摄像头窗口，留线束弯折与插拔空间。检查镜头与 ToF 开口的遮挡、外壳和屏幕反光，锁定摄像头角度后重新标定。
3. 加固 USB-C 口和线束，使插拔力由支架承受。让实体停机键可快速按到，关机键、语言键和指示灯易辨认。合盖后手转车轮、摇动机身，检查是否擦轮、挤线或松动，再通电测试。
4. 用同一台机器、同一位置、同一组口令对比开盖和合盖。记录 CPU 温度、是否降频、两种语言的时延、拾音与唤醒率；根据测量调整声孔、风道或风扇，再复测。

### 5.3 整机复测与证据

| 项目 | 操作与判据 |
|---|---|
| 独立运行 | 关闭笔记本，断网并以机载电池冷启动。检查就绪提示，验证中文和英文各自能被同一唤醒词开启，会话能连续追问且音色切换正确。 |
| 拾音与温升 | 安静桌面唤醒至少 18/20。按第 2 阶段的双语题组复测切题率、上下文和首播时延，记录连续运行时温度和有无降频。 |
| 运动保护 | 重跑架空方向和实体停机，系绳复测前、后、斜向、转向及桌角。记录装壳后视觉和 ToF 停车余量，复测摄像头故障、联锁超时和恢复。 |
| 表情屏 | 查看待机、听取、处理、播报、停机表情。架空模拟拔屏或刷新超时，确认保护仍按时停轮。 |
| USB-C 与电池 | 装壳后复测 3 次关机充电循环和充电互锁，以及至少 30 分钟对话与移动混合运行。 |
| 交付 | 保存实际 BOM、接线图与针序、固件及软件版本和启动方法、CAD 源文件与 STL、测试记录、断网演示。 |

验收记录至少写明阶段、日期、软硬件版本、桌面或供电条件、测试输入、预期、实测和证据文件。按通过、失败、未测分开记录。固件和部署步骤由助手准备，实物装配与现场操作由用户完成，双方依据日志和测量结果确认。

**采购顺序**。先配齐第 1 批台架。板上对话通过后买 ESP32-S3、I²S 麦克风和数据线，核完 GPIO 后配表情屏。唤醒和通信打通后买双轮与桌沿件，USB 摄像头可先借用验证视野与焦距。电池管理在包含摄像头和屏幕的负载测量后选型，外壳在实物装配尺寸确定后打印。
