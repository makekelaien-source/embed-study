# 摄像头反馈与表情屏：下一阶段接口和验收规格

2026-11-12。适用对象：Orange Pi 4 Pro A733＋ESP32-S3＋**履带底盘**。这是后续实现规格，不是已上板能力或防坠性能声明。先结束当前语音单元，再按本文分步联调；现有材料中“两轮前方”的几何与物料不能直接沿用到履带底盘。

## 1. 当前代码能做什么

| 文件 | 已有能力 | 明确缺项 |
|---|---|---|
| [vision_check.py](../vision_check.py) | 对固定参考和固定ROI作4×4分块外观比较，输出CLEAR／EDGE／UNKNOWN；支持图片回放、有限帧相机采样 | 连续采集服务、可信帧龄、读帧超时、看门狗、队列控制、完整模糊／遮挡判定、实车桌沿识别均未实现 |
| [face_screen.py](../face_screen.py) | 导出五种表情PNG、240×320 RGB565及旧单色素材；支持自备PNG | LCD固件、DMA调度、状态协议、故障／离线／电源新素材均未实现 |
| [forward_guard.h](../forward_guard.h) | 既有前进许可与动作时限接口，软件上限分别200ms、300ms | 不覆盖履带后退／转向；上限不是实车安全时限证明，不能由此推断可用速度 |
| [原视觉与屏幕清单](../vision-face-runbook.md) | 台架流程、素材和前进联锁接入说明 | 旧双轮覆盖、固定参考算法与既有数字须按履带实物重新核验 |

现有`CLEAR`只表示指定区域外观像参考。其`EDGE`启发式依赖远端整行变化、近端保留，不能可靠覆盖单侧、斜向、低反差或相似纹理边缘；移动后纹理平移也可能产生UNKNOWN。梯度与曝光检查不能冒充完整的遮挡、模糊或深度检测。冻结旧帧仍可能持续得到CLEAR。当前程序不能直接给运动系统发“可以前进”。

## 2. 执行边界和优先级

| 优先级 | 运行职责 | 时间与失效约束 |
|---|---|---|
| 最高 | ESP32本地实体停机、ToF有效性、运动时限、通信／视觉许可到期 | 独立于香橙派、语音、摄像头和屏幕；任一否决立即停轮，恢复后等新指令 |
| 高 | 香橙派相机时效监控、方向覆盖与危险／未知状态撤销 | 不能等待LLM、TTS、表情刷新或用户在场检测 |
| 普通 | 语音处理、对话状态反馈 | 保留现有单元的资源与故障边界 |
| 低 | 表情更新、可选用户在场／人脸位置反馈 | 可跳帧、降频或停用；不能占用停机锁或续期运动许可 |

第一版采用低分辨率传统视觉和明确的三态接口，不把重型VLM加入基线。当前A733已有语音负载下温升／停测问题，后续联合实验沿用本轮**CPU 70°C停止实验**的门槛，并保留内核及其他热区保护；这不是修改系统临界关机温度。温度、设备状态或资源预算不可确认时，不叠加新负载，也不继续运动测试。冷却后恢复由健康检查决定，不能自动续跑旧动作。

## 3. 采集适配层：最新帧与可信时间

### 3.1 进程和缓冲约束

1. 摄像头由独立采集工作进程持有，分析器与语音进程不直接执行阻塞`read()`。工作进程内部使用已验证的有限等待；监督者不依赖该进程自己报告“仍健康”。
2. 应用层只保留一个最新帧槽位，不建无界FIFO。图像与元数据原子发布，消费者持有不可变副本或有所有权的有限缓冲；不能在DMA／驱动归还缓冲后继续引用其旧地址。
3. 应用槽位为1不代表驱动没有积压。记录实际驱动缓冲配置并验证端到端帧龄；必要时在适配层排空已完成缓冲，只分析最新合格帧，统计丢帧而不追赶历史队列。
4. 打开、协商、读帧、解码、分析均有监督截止时间。读帧超时、子进程失联或输出无进展时先撤销许可，再清理／重建采集进程；线程取消、`join(timeout)`或另一个线程调用`release()`不能当作已证明可终止底层阻塞。
5. 摄像头重连、分辨率／格式变化、时钟类型变化时增加`camera_epoch`，清空旧帧、连续CLEAR计数和许可，重新核对标定。设备名优先按实际`by-id/by-path`绑定，不把某次`/dev/video0`编号当固定身份。

Linux V4L2缓冲提供`sequence`、时间戳和时间戳类型／来源标志；`CLOCK_MONOTONIC`、未知时钟、帧末接收EOF与曝光开始SOE不能混用。具体语义按实际驱动标志核对。[Linux缓冲文档](https://docs.kernel.org/userspace-api/media/v4l/buffer.html)

OpenCV的`CAP_PROP_OPEN_TIMEOUT_MSEC`和`CAP_PROP_READ_TIMEOUT_MSEC`是打开时参数，官方限定FFmpeg／GStreamer后端；不能据此保证本项目`CAP_V4L2`的`read()`有上界。设置`CAP_PROP_BUFFERSIZE`也须核验实际后端行为。先用OpenCV做诊断，移动前选定能够取可信采集时间并验证阻塞边界的适配实现。[OpenCV属性文档](https://docs.opencv.org/5.0/main_modules/videoio_flags_base.html)

### 3.2 帧数据契约

下表是主机内部帧封装与采集适配器的逻辑字段，不是串口负载。当前可运行框架的实际字段以[wire.py](wire.py)为准：`vision`负载严格只有`token/frame_id/state/remaining_ms`，外层另有`v/link/seq/kind/crc32`。不能把下表中的设备、相机epoch、标定或方向字段直接加到现有JSON里。

| 字段 | 约束 |
|---|---|
| `camera_epoch`、`frame_id` | 本次采集会话与递增应用帧号；驱动`sequence`另存，重复／倒退／重连须识别 |
| `device_id`、实际尺寸／格式 | 与标定一致，保留协商结果，不只保存请求值 |
| `driver_timestamp`、时钟类型、SOE／EOF标志 | 验证后才能参与安全帧龄；未知不能伪装成可信时间 |
| `observed_monotonic_ns` | 对应本帧最早有效观察时刻的保守估计；若仅有EOF，须扣除经测量约束的曝光／读出时间；未知上界则该帧不发许可 |
| `dequeued_monotonic_ns`、分析起止时刻 | 同一主机单调时钟，区分驱动积压和计算延迟；读帧返回时间不等于采集时间 |
| 对应poll的`token`、主机收讫时间 | 主机保存当前控制会话收到该poll时的单调时间；签发CLEAR的帧必须在此后才被实际采集 |
| `calibration_id`、ROI／覆盖版本 | 绑定镜头姿态、桌面、分辨率、参考图和履带外廓；不匹配即UNKNOWN |
| 图像所有权、错误／丢帧标志 | 使用期限明确；损坏、部分帧、时间戳异常不能发布CLEAR |

香橙派上安全计算显式使用与已验证V4L2时间戳一致的单调时钟。不能用系统墙钟、视频文件播放位置，或“读到帧后重新打一个现在的时间”续期旧图。ESP32用自己的本地单调时钟计时；两端未经同步不直接相减绝对时间戳。

## 4. 履带覆盖与桌面资格

### 4.1 先量几何，再确定允许方向

- 实测两条履带的接地长度、宽度、外侧间距、机身突出部位和重心，建立保守矩形支撑／外廓包络；不能仍用两个轮子的中心点代替。
- 对每个允许动作计算并实测整个动作期间的**扫掠区域**。后退检查后方；差速／原地转向的前后外角会向侧面外扫，不能只检查车头或动作终点。履带打滑、桌面材质、载荷和供电变化会改变实际转弯范围。
- 标定镜头到桌面的投影，使安全ROI覆盖该动作的危险接地点、前瞻距离与停车余量。前置单摄不能授权其视野外的后退、侧向扫掠或后角；可先仅开放验证过的直线前进。
- 后方／侧方ToF等独立感知未覆盖并验证的方向，运动适配器保持禁用。前后各一只ToF也不自动等于全方向防坠。
- ESP32在本地组合各方向需要的ToF、实体停机、通信和时限条件；任何无效读数、超时或覆盖缺口均否决。香橙派视觉许可和LLM描述都不能覆盖本地否决。

设某危险接地点到桌沿的最小实测提前量为`D_lead`，验收应满足：

`D_lead > V_max × T_reaction_worst + D_stop_worst + D_margin`

`V_max`取所检查危险接地点／外角的最大线速度，不能统一用底盘中心速度。原地转向时中心平移速度为0，外角仍有由角速度和转动半径产生的扫掠速度。`T_reaction_worst`覆盖曝光／采集间隔、驱动积压、分析、通信、控制周期及故障后许可到期才停的最坏路径；使用实测最坏上界，不用平均值或P90替代。`D_stop_worst`分别测制动和断驱滑行；转弯时按最先越界的履带／外角及实际扫掠路径核验。未测的数据写未测，不先给可用速度。

### 4.2 桌面按条件准入

| 表面／场景 | 首轮处理 | 准入需有的证据 |
|---|---|---|
| 哑光、有纹理、不透光平面 | 可作首轮静态标定候选 | 直边／斜边／桌角、不同朝向与允许光照下的标注回放和系绳实测 |
| 深黑、低反射或低纹理面 | 默认未获准 | 相机质量判定与ToF有效率均达到该场景要求；不能把黑色直接解释为桌沿或安全桌面 |
| 玻璃、透明、镜面、高反光面 | 首版保持禁用 | 需要独立覆盖与专门验证；RGB外观或“能看见桌子”的语义不能证明承重面连续，ToF也须另核查材质适用性 |
| 缝隙、孔洞、桌角、桌布悬垂 | 视为独立危险场景 | 覆盖每条履带接地带及扫掠范围；桌布／影子／近似背景不得作为连续承重面的证据 |
| 强背光、暗光、移动光斑、污渍／遮镜 | 不合格帧UNKNOWN | 先证明质量门能拒绝不可靠画面，再验证停止响应 |

准入记录绑定桌面材质、允许光照、相机姿态、车重和速度范围。更换桌面／镜头角度、挪动支架、合盖遮挡或改变载荷后重新核验。语义识别“这是桌面”不能替代几何、质量、时效和独立传感器证据。

## 5. 从候选分类到有限许可

### 5.1 三态与消抖

| 状态 | 含义 | 对运动的输出 |
|---|---|---|
| `CLEAR`候选 | 本帧在已准入条件下，参考／ROI、质量、几何覆盖和时效全部合格 | 仍需连续不同新帧达到配置数量，才发布有时限的方向许可 |
| `EDGE` | 发现所需支撑区域中可能的桌沿／缺失 | 当帧撤销并清零CLEAR连续计数，不等待多帧确认才停 |
| `UNKNOWN` | 模糊、曝光异常、遮挡、配准失败、信息不足、未准入表面、旧帧或故障 | 当帧撤销；不能把上次CLEAR继续沿用 |

恢复CLEAR可先以3个连续合格新帧作台架候选，最终数量与最大帧间隔由误检／漏检和响应预算确定。只有“允许恢复”消抖；危险／未知／超时立即撤销。重复处理同一帧不能累计连续帧数或续期许可。

质量判定至少覆盖参考有效性、ROI边界、纹理可判断性、运动模糊、曝光、局部遮挡及几何配准。阈值须在已标记实拍数据上确定并保留独立验证集，不把当前`vision_check.py`的固定差值／梯度阈值当作通用参数。移动后可比较受限配准、几何边界或其他轻量方法；未经验证的固定像素模板只保留诊断用途。

### 5.2 许可时间契约

- 主机在当前控制会话中记录收到每次poll的本地单调时间。CLEAR必须使用**实际采集时刻严格晚于对应poll主机收讫时刻**的新帧；新token不能包装poll之前已缓存的图像，也不能给旧像素换一个新帧号重发。相机时间来源、主机时钟和帧龄仍须先验证；若只有无法确定观察时刻的时间戳，则发UNKNOWN。
- 相机`camera_epoch`、`calibration_id`、ROI／方向覆盖版本都留在主机内部，与当前`link`和唯一`frame_id`关联。跨相机重连、标定变化或控制会话变化时清空该关联与CLEAR计数。v1实际发送`vision={token, frame_id, state, remaining_ms}`；其中视觉CLEAR仅用于FORWARD。后退／转向由显式`safe_actions`和本地`direction_ok`覆盖准入，不能靠添加一个未定义的串口方向字段放行。
- 发送前按**采集／观察时间**扣除已消耗帧龄与保守传输上界。剩余时间必须为正整数毫秒，且不超过实车核定上限及现有200ms软件上限；负数、未知时间或超限一律不发CLEAR。[supervisor.py](supervisor.py)的`host_vision_payload`校验同一主机时钟上的poll收讫、采集和分析时间；调用者仍须先算好已扣除开销的剩余时长，辅助函数不会替代真实相机采集时钟的验证。
- MCU在自己的时钟上签发token并固定其原截止。当前仿真最多保留两个未到期token；示例配置为100ms一次poll、200ms固定token窗口，poll频率与更快的安全tick分开。这是代码约束／示例，不是实物已测时序。收到CLEAR时许可截止取`min(token原截止, 接收本地时刻 + remaining_ms)`；回复、心跳或换新消息seq都不能推迟该token原截止，两端绝对时钟不直接相减。
- 每个CLEAR需递增且未签发过许可的`frame_id`。该帧号在当前控制`link`内持续递增，不因相机`camera_epoch`变化就从1重新开始；必须重置或即将到计数上限时先完成新link握手。重复／乱序／旧会话许可不能续期；普通心跳和屏幕状态不能更新视觉截止时间。
- 撤销／停止用**同一发送方向内的新消息seq**，在实际发送时分配，优先送出；不是另建一套STOP序号空间。v1撤销编码为`kind=vision`、`state=EDGE/UNKNOWN`、`remaining_ms=0`，可以引用旧token或最后一帧ID；当前会话的新seq有效时，不能因同帧曾发CLEAR而忽略撤销。`kind=stop`仅带`command_id`，不要求新token或视觉许可。撤销丢包仍由本地许可到期及独立传感器停轮。
- 条件恢复仅恢复接受**新口令**的资格，不自动恢复原动作或消费故障前积压指令。

以下为安全封装的伪代码，`classify_roi_candidate`等仍是待实现／验证的适配接口；不宣称已经有可靠桌沿算法：

新序号／新时间戳只能证明数据接口有进展，不能证明传感器没有把同一画面重复包装。完全静止场景也可能合法像素相同，因此不能靠图片哈希解决全部冻结问题。对“内容冻结但仍产生新时间戳”的故障须单列验证并依赖独立感知／限制运行范围；没有证据时不能宣称相机独立覆盖该故障。

## 6. 用户在场与画面反馈

第一层反馈是明确状态与原因，例如相机离线、画面不可判断、前方支撑面异常；危险先停轮，语音说明和屏幕随后完成。日志保留状态、帧号、时间、质量分项、覆盖版本和撤销原因。日常不默认保存连续原始视频；诊断样本由明确测试窗口另行保存并标注真值。

用户在场／人脸位置是可选的低优先级交互功能，可用于屏幕注视方向或切换表情，不能产生运动安全许可。首版先不加载人脸模型，也不据此驱动履带转向；后续若增加“朝向用户”动作，只能产生交给运动联锁审核的高层意图。测清CPU／内存／温度余量后再添加限频检测。人脸未检出不等于无人，检出人脸也不等于确认身份。

前下方安全镜头不一定能同时看到用户脸部。若需要另一个视角，先评估独立交互摄像头；不能为了看人而抬起正在承担安全覆盖的镜头。任何姿态变化使原标定失效时立即撤销许可。跟人移动、手势驱动、视觉语言问答属于再后续能力，不从“检测到有人”自动推出。

## 7. ESP32表情屏

### 7.1 素材、格式和内存

- 基线为ST7789系列240×320竖屏，实际模块、色序、方向与供电按到手板核对。现有五态是`idle/listening/thinking/speaking/blocked`。
- 当前`.rgb565`无文件头，按行从左到右、从上到下，每像素两字节，**高字节先存**。单帧153,600字节（150KiB），五帧768,000字节（750KiB）。PNG用于离线预览／导出，不假定固件已有PNG解码器。
- 自备PNG当前会等比例缩放、居中，透明区合成到固定背景。更换人物不改变状态协议和安全优先级。
- 素材包须带尺寸、格式、字节序、长度、校验和与版本。只在停机维护状态更新；长度不符／资源缺失时退回内置故障提示，不读取越界数据。
- 先跑红绿蓝色条和四角标记；避免把高字节先存文件直接按小端`uint16_t`解释，或软件和LCD驱动各交换一次导致重复翻转。

### 7.2 未来显示状态优先级

| 优先级 | 逻辑状态 | 显示与本地动作 |
|---|---|---|
| 最高 | `power_critical/shutdown_pending` | 先停轮并按电源框架处理；有时间再显示电源提示，关机不能等待屏幕 |
| 高 | `blocked` | 实体停机、桌沿、ToF否决、方向未获准等警觉表情，覆盖正常对话表情 |
| 次高 | `fault` | 相机／采集／控制器／资源异常；运动许可已撤销，显示故障原因 |
| 次高 | `offline` | 主控未就绪或通信失联；保持本地禁止运动，不显示虚假的就绪状态 |
| 普通 | `listening/thinking/speaking` | 由实际收音、有限时处理、真实播放状态驱动；三态按对话状态机互斥 |
| 最低 | `idle` | 正常就绪且无更高优先级状态时显示待机 |

`fault/offline/power_*`目前只是规划逻辑状态，现有导出CLI不支持这些名称；新素材和协议未实现前可映射到已有`blocked`，原因由独立状态字段／日志提供。屏幕失效不改变停机逻辑。

### 7.3 刷新与硬件适配接口

安全／通信任务只写入原子状态快照或短临界区的最新状态槽；不直接调用LCD API。低优先级显示任务读取快照，更新队列只保留最新目标状态，旧动画可丢弃。显示不得持有电机／ToF安全锁，不得让控制任务等待SPI或图像缓冲。

ESP-IDF提供ST7789与SPI DMA接口、传输队列和完成回调；DMA缓冲在传输完成前不能被复用。官方示例参数不是本项目时序保证。[ESP-IDF SPI LCD文档](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/lcd/spi_lcd.html)

先比较8／16行条带：240宽RGB565分别为3,840／7,680字节；双缓冲占7,680／15,360字节，另计驱动和状态内存。是否可直接从PSRAM DMA、对齐和分配能力取决于实际ESP-IDF版本／芯片／驱动，先锁版本再确认，不能假定全部PSRAM都满足DMA要求。

```text
DisplayAdapter.initialize(actual_board_config) -> READY | UNAVAILABLE
DisplayAdapter.submit_latest_state(snapshot) -> UPDATED | BUSY | UNAVAILABLE
DisplayWorker.submit_one_strip(owned_buffer, deadline) -> QUEUED | BUSY | ERROR
on_color_transfer_done(buffer_token) -> 标记缓冲可复用并通知显示任务
```

以上只是固件适配器契约，尚无可直接烧录实现或GPIO针脚表。SDK的队列提交也可能等待可用槽位；只放在显示任务内，并设置／实测适配器的阻塞上界。缓冲忙则跳过刷新，不积压整帧。完成回调只做短通知，不解码图片、等待锁或调用运动逻辑。显示超时由显示任务恢复；重置LCD、DMA异常和总线锁均要纳入停机时序的故障注入测试，不能仅靠“低优先级”就宣布不影响控制。

实际ESP32板、LCD模块、Flash／PSRAM、USB、I²S、ToF和电机适配器确定后再分配引脚并核对资源冲突。暂不填想象中的针脚号或驱动能力。

## 8. 实施顺序与验收

| 步骤 | 交付 | 通过条件与边界 |
|---|---|---|
| 0. 语音单元收口 | 当前配置／回退点／已通过与未通过项 | 当前语音稳定性和热状态有明确记录；视觉不掩盖未完成的识别／回答问题 |
| 1. 实物与覆盖登记 | 履带尺寸、相机视野、ESP32／屏幕版本、传感器布局、供电检查 | 每个方向有覆盖图；无证据的方向明确禁用，不按旧双轮数据放行 |
| 2. 标注图片回放 | 合格桌面、直／斜边、桌角、遮挡、模糊、反光、黑面与玻璃负例 | 独立验证集单列各场景漏危险／误CLEAR／UNKNOWN比例；关键危险样本不得误发运动许可，未准入表面保持禁止 |
| 3. 有时效采集 | 最新帧工作进程、时间戳检查、监督者和有界重启 | 电机断开，复现积压、阻塞、旧戳、重连、停进程；所有故障能在配置上界内撤销，记录最坏值 |
| 4. 表情屏台架 | 色条、五态素材、状态槽、条带DMA与故障映射 | 方向／色序／字节序正确；刷新忙、拔屏、SPI卡住时控制／停机路径仍满足上界 |
| 5. 控制链干跑 | 会话、唯一帧许可、独立撤销、ToF本地否决、动作适配器桩 | 不接电机验证旧会话、重复／乱序、TTL归零、心跳不续期、未知立即撤销、恢复不自动续跑 |
| 6. 架空和地面围挡 | 实际履带驱动、单方向准入 | 上电／重连不自行运动；逐方向验证实体停机、断链、ToF异常、相机异常；先测停机再定速度 |
| 7. 系绳桌面 | 允许材质、每方向／转向扫掠、最坏停车距离 | 防坠绳独立固定；每个关键场景至少10次有限试验并列分母，全部停在实测余量内；任何失败先禁用该条件，不用平均值抵消 |
| 8. 联合负载与合盖 | 语音＋相机＋屏幕＋许可＋低速运动 | 受控30分钟目标，CPU达到70°C即停实验；记录最低供电、电机启动、帧龄、最坏停机、音频掉线／丢帧和温度，未完整跑完不记通过 |
| 9. 冷启动与后续 | 断网自启、设备恢复，再转电池／充电／外壳单元 | 本地健康条件全部就绪后才允许新动作；更换电源／装壳后重跑温升、覆盖和停车测量 |

10次、30分钟等为拟定有限样本验收量，不是可靠性或所有桌面无跌落的保证。实际试验由助手准备可审阅的软件／日志，用户完成装配、摆位、系绳及现场物理操作；未到货／未连接／未测项目明确保留。

## 9. 失败矩阵

| 注入／现象 | 必须观察到的行为 | 不得当作通过的替代证据 |
|---|---|---|
| 摄像头拔除、打开失败、读帧永久阻塞 | 监督者撤销；ESP32本地许可到期停轮；有界清理重试 | 主进程仍active、旧CLEAR还在屏幕上 |
| 老图延迟返回、驱动缓冲积压 | 按原采集时间拒绝，不重新打现在的戳 | 只把应用队列长度设成1 |
| 重复／倒退帧号，未来／未知时钟，重连旧会话 | 清计数、撤销、重新握手和标定核对 | 心跳正常就继续续期 |
| 模糊、遮镜、曝光极端、参考／ROI变化 | UNKNOWN当帧撤销，恢复须连续新帧并等新动作 | 旧参考仍能算出一个相似度分数 |
| 正在转向时后外角靠近桌沿 | 覆盖该扫掠区的独立感知停轮；无覆盖则事先禁用该转向 | 前置相机仍看到正前方桌面 |
| 单只／多只ToF超时或无效 | ESP32直接否决对应动作，CLEAR不能覆盖它 | 相机说桌面存在、人眼觉得还有距离 |
| 黑面／玻璃／缝隙未获准 | 始终不发布该条件的运动许可 | RGB语义标签“桌子”或一次测距数字看似正常 |
| 分析／人脸任务变慢、语音高负载 | 丢弃旧帧、过期撤销；降低或停用低优先级任务 | 平均FPS达标却存在长尾旧帧 |
| 内容冻结但设备继续生成新戳 | 单列系统级验证、依赖已验证的独立感知并限制范围；未覆盖不宣称相机可保护 | 单调帧号或图片哈希不变就断言已定位／排除冻结 |
| LCD拔除、DMA回调丢失、刷新队列满 | 显示超时／丢刷新；本地停机时序不受影响 | 表情先刷新完再执行STOP |
| 许可撤销包丢失、串口断线、香橙派重启 | 独立ToF／实体停机继续有效，有限许可到期；旧动作清空 | 普通心跳、旧帧或屏幕指令补发续命 |
| 联合负载温度到70°C、供电压降／USB重连 | 停实验、停轮、撤销；保留日志，先恢复稳定性 | 降低日志频率掩盖异常或关闭系统温控 |
