## 1. 本阶段要完成什么

- 香橙派独立完成“听到人声 → 识别文字 → 结合上下文生成回答 → 合成语音 → 音箱播放”。
- 支持中文、英文两种模式，分别保存音色和语速；当前切换语言需要重启语音进程。
- 开机自动加载模型、静默预热，完成后播放就绪提示音，无需电脑代算或按 Enter。
- 验证断网可运行，并记录识别、模型输入处理、生成、合成和首声等待。

ESP32唤醒词、移动底盘、防坠联锁、摄像头、表情屏、电池及USB-C充电属于后续实物阶段。当前移动口令只在台架打印模拟动作，不驱动电机。

## 3. 当前链路与配置

```mermaid
flowchart LR
    A[USB麦克风] --> B[音量检测与说完判定]
    B --> C[SenseVoice识别]
    C --> D[Qwen多轮对话]
    D --> E[首段切分与语音合成]
    E --> F[USB音箱]
```

开机服务先寻找USB音频设备，再加载模型并静默预热。就绪提示音之后可直接说话；播完自动听下一句。当前尚无唤醒词门槛，后续接ESP32再改为唤醒待命。

| 配置项 | 当前选择 |
|---|---|
| 模型生成 | 2线程，cpu6–7大核 |
| 模型输入处理 | 8线程，cpu0–7 |
| 语音合成 | 8线程；4线程对照未体现优势 |
| 提示词 | 保留原版，压缩版未体现稳定收益 |
| 中文首段 | 16字软上限；保护数字、英文词和成对符号；保护跨度可超过上限 |
| 收音 | RMS检测，门限0.004，结束静音0.55秒 |
| 可选收音方案 | Silero VAD已准备，当前未设为默认 |
| 会话记忆 | 最近4轮上下文；不含跨进程、跨开机的长期记忆 |
| 无效识别 | 纯标点不送入模型；“嗯”“哈哈”等正常短表达仍保留 |
| CPU频率 | 人工1.716GHz上限已解除；大核恢复硬件公布的2.002GHz上限，内核调频及温度保护保留 |

0.45秒结束静音会截断已知的半秒句中停顿，未采用。Silero在现有真人录音上的结束判定比RMS更慢，所以先选RMS＋0.55秒，仍需真人验证轻声、停顿和背景噪声。

中文说整句“结束对话”，英文说`End chat`可结束当前会话。开机服务模式会清空上下文并继续等待下一句；手动调试模式回到等待Enter。

## 4. 日常使用与维护

### 4.1 正常开机

1. 断电时插好系统卡、接好USB麦克风和音箱，再接稳定电源。
2. 系统自动启动`desktop-robot.service`，寻找音频设备并加载模型。
3. 等一次短提示音，再开始说话。上次重启实测约59秒就绪，其中服务加载约49秒；这是一次测量，不是固定启动时长。
4. 使用中轮流说话：机器人播报结束后再开口，当前没有边播边听的打断功能。

首次配置和远程维护需要电脑；模型准备好后，机载对话计算可独立进行。

### 4.2 SSH与状态查看

网线用于远程操作，不负责把电脑算力转给香橙派。`192.168.137.72`是之前使用的地址，重新连接后应核对实际IP。

在已配置登录凭据的Windows PowerShell中：

```powershell
$boardAddress = Read-Host '输入香橙派当前IP'
ssh "orangepi@$boardAddress"
```

以下命令在香橙派SSH终端执行：

```bash
cd ~/desktop-robot
systemctl status desktop-robot.service
systemctl is-enabled desktop-robot.service desktop-robot-frequency.service
cat .local/service-ready.json
journalctl -u desktop-robot.service -n 30 --no-pager
cat /sys/devices/system/cpu/cpufreq/policy6/scaling_max_freq
```

`Offline voice ready`表示模型已完成就绪流程；仍需实际听到回复才能确认整条声学链路。频率上限不等于实时频率，温度保护可能降低实际运行频率，不应为追求读数关闭保护。

### 4.3 切换默认语言、音色与语速

中文和英文复用识别及聊天模型，分别使用自己的合成音色。下面的语言切换命令会覆盖该环境文件；如果已经自行增加其他配置，请只修改`ROBOT_LANGUAGE`那一行。

```bash
# 下次启动使用英文
printf 'ROBOT_LANGUAGE=en\n' > .local/robot-service.env
sudo systemctl restart desktop-robot.service

# 改回中文
printf 'ROBOT_LANGUAGE=zh\n' > .local/robot-service.env
sudo systemctl restart desktop-robot.service
```

- `.local/voices.json`：`zh`、`en`分别保存音色，当前为`theresa`、`lessac`。
- `fast-profile.json`：`language_overrides`分别保存中文0.9、英文1.0语速。
- 修改后重启服务；放慢语速是听感调整，不应算作响应加速收益。

### 4.4 手动测试与正常关机

手动测试前先停自启服务，避免抢占麦克风、模型端口与CPU。设备编号只是上次枚举结果；手动执行前用`--devices`确认，开机服务则按名称自动选择。

```bash
cd ~/desktop-robot
sudo systemctl stop desktop-robot.service
.venv/bin/python robot.py --devices
# 上次输入编号0，输出编号3；如枚举变化，应替换
.venv/bin/python robot.py --audio-check --input-device 0 --output-device 3
.venv/bin/python run_fast.py --language zh --metrics .local/human-fast-zh.jsonl
# 按Ctrl+C退出手动聊天后，恢复自启服务
sudo systemctl start desktop-robot.service
```

正常关机：`sudo shutdown -h now`。等待系统正常停止后再断电。

## 6. 测试结果：哪些已经证明

### 6.1 录放音与真人反馈

- 10秒麦克风录音回放：用户确认清楚听到自己的话。
- Theresa 0.9语速试听：用户确认“语速还可以”。
- 正常重启后的两句中文对话：用户确认两句均能正常回复。
- 以上不等于完成中文、英文各15轮真人验收，也不能据此给出真人P90成绩。

### 6.2 固定输入加速对照

下面是“文件输入到首段音频就绪”，不含真人结束静音等待和实际音箱缓冲；每组只有3轮。

| 对照 | 三轮等待/首轮等待 | 结论 |
|---|---|---|
| 同一真人录音，冷入口与预热入口 | 首轮8.87秒→4.20秒 | 将首次模型处理移到启动阶段；预热本身仍需时间 |
| 固定随机种子，2线程输入处理 | 4.27 / 3.30 / 4.73秒 | 对照 |
| 相同输入和随机种子，8线程输入处理 | 3.77 / 2.89 / 3.78秒 | 当前采用；小样本不能推算所有聊天的提速倍数 |
| 更换中文音色为zh-ll-0 | 有较小收益 | 优先保留用户选定的Theresa |
| Qwen3-0.6B候选 | 前两句快，第三句约6.30秒 | 中文内容预检11/15，未达12/15，不替换1.7B |

### 6.3 已完成的离线长测

**条件是旧配置：大核上限1.716GHz、2线程输入处理、Theresa 0.9；不等于当前额定频率＋8线程配置。**

测试进程树置于独立网络空间，没有Wi-Fi/以太网接口和外网路由；SSH维护通道位于外部，不参与推理。

| 项目 | 结果 |
|---|---|
| 时长与批次 | 31分6秒，7批，共105轮，退出码全部为0 |
| 中文文件输入 | 60轮，中位数5.24秒，P90 6.78秒 |
| 英文文件输入 | 45轮，中位数4.60秒，P90 5.90秒 |
| 温度 | CPU采样峰值90.742°C，散热仍需复测 |
| 限制 | 没有持续播放音箱，不证明30分钟实际播报无断音，也不证明整机断网冷启动真人验收通过 |

中文中位数仍超过5秒目标，部分批次P90也超过8秒；英文存在shape→sheep等误识别及上下文失败。不能把“运行退出码0”写成“全部质量与速度达标”。

板端/本机证据目录包括`.local/speed-ab-01/`、`speed-ab-02/`、`speed-ab-03/`、`speed-offline-soak/`以及`vad-comparison.json`。自启动证据还包括板端`startup-before-reboot.json`、`startup-after-reboot.json`、`service-ready.json`与journal。
