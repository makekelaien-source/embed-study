用户已确认唤醒回应、结束提示和音量语音控制可用，但指出唤醒与聊天收音准确性有波动。单次功能成功不代表识别准确率验收通过。本轮检查代码、配置及既有校准记录，仅更新方案，未修改板端运行参数、重启服务或开展新的真人录音。

当前聊天为 RMS -46 dBFS、连续200ms起音、200ms前置缓存、550ms尾静音；唤醒为120ms起音、200ms前置缓存、560ms尾静音，并用SenseVoice日语转写后匹配Naruto。之前真人回放仍有命中与漏检，不能记为稳定唤醒。正常与目标小声样本的电平重叠，且小声样本有较大瞬态，仅调固定门槛无法可靠区分。播报期间当前未收音，过早接话属于另一类漏收，不能混入ASR错字率。

按以下顺序实施，每步使用同一组有标注音频对照，保留原版回退；下列数值是待验证候选：

1. **先定位丢音环节。** 在明确开始/结束的诊断测试期间，记录原始测试音频、实际送识别的片段、起止时刻、转写、溢出/丢帧、唤醒接受结果；生产日常对话不默认持续保存原始录音。分别统计没触发、截首尾、转写错误、播放中说话四类问题。保持同一输入设备、增益和距离，按每个进程解析设备名称。
2. **先保住首尾，再调灵敏度。** 聊天前置缓存从200ms比较400/500ms，起音从200ms比较120/80ms；缓存是滚动保留，不必额外等500ms才识别。先保持-46 dBFS与550ms尾静音不变，逐项对照；存在停顿截句时再单独比较650/700ms，并统计新增延迟。唤醒与聊天起音、缓存、门槛拆开配置，避免一个参数牵动两种场景。聊天采集可复用唤醒已采用的独立回调队列，减少推理占用导致丢帧，实际收益须测。
3. **补充人声判断与噪声适应。** 对比现有RMS与RMS底线加轻量VAD；背景噪声估计只在确认无语音时更新，并限制阈值上下界。启动与持续讲话使用不同阈值，防止轻声尾字提前结束。此项不能过滤所有旁人讲话，也不保证更快；同时报告漏检、误触发、CPU与延迟。
4. **单独优化Naruto。** 用用户实际发音、常用距离、不同音量的正例，及近音词、环境对话、机器人自身音频的反例复测当前短句识别。先改善截音，仍不稳再比较专用关键词检测/定制模型与现有转写方案。旧KWS在真人样本上曾无命中，不直接切回；不得把“然后”“なるほど”等常见词加入接受列表换取表面召回率。
5. **分开处理接话时机。** 短期明确固定回应/回答播放结束后才可接话；后续若要边播边听，应另做连续采集与回声消除，并用自播音频回灌测试。单纯缩短播报后等待或重新开麦不能等同于实现可打断对话。

验收先覆盖用户常用距离，再分别测试更远、轻声和噪声场景：Naruto至少19/20次成功；20条非唤醒/近音词不误唤醒，10分钟环境声观察无误唤醒；20条聊天测试检查首尾完整，另报中文字符错误率与音量命令正确执行率。不同场景单列分母，不以整体平均掩盖某场景失败；同时报告首响延迟P50/P90，不以延长等待掩盖准确性问题。这些均为目标，当前未完成统计验收。

摆位先固定麦克风朝向用户、避开风扇直吹与桌面振动、与扬声器保持分离；用同句录音验证效果。完成软件及摆位对照后仍存在明显距离限制，才评估有指向性/回声消除能力的拾音硬件，采购由用户决定。

技术参考：[sherpa-onnx VAD接口](https://k2-fsa.github.io/sherpa/onnx/c-api/html/vad.html)支持独立设置最小语音/静音时长；[KWS模型文档](https://k2-fsa.github.io/sherpa/onnx/kws/pretrained_models/index.html)说明chunk与延迟/准确性的取舍。上述80/120ms等候选来自本项目对照方案，不是官方保证值。

## 总体目标与顺序

先保证回答有用且闭环，再在同等质量下加速；收音校准及本地工具可作为独立单元推进。每次改变保留前后版本、同输入对照与回退记录。没有待执行任务的普通聊天不允许许诺稍后完成。

| 顺序 | 工作 | 交付与验收 |
|---|---|---|
| P0 | 备份板端源码、profile、音色设置，记录模型、服务、温度与线程 | 可恢复原版本；保留原始日志，不复制密码 |
| P1 | 复现回声与“思考后搁置” | 区分ASR错误、模型复述、输出截断、TTS/队列丢失、上下文影响；每类至少3个固定输入案例 |
| P2 | 修复回答质量与完成状态 | 知识题给结论与解释；追问提供新信息；未知明确说明；失败和截断有可见结果，不静默放弃 |
| P3 | 校准收音 | 噪声/小声/正常语音分组；dBFS门槛与持续起音联合对照 |
| P4 | 落地语音工具 | 先部署直接音量工具，再增加模型语义理解与受限工具调用；依据执行结果回执 |
| P5 | 同质量下压缩响应 | 按识别、首token、首段、合成、播放实测耗时优化；比较8/12/16字首段及必要的流式识别 |
| P6 | 开机与综合验收 | 重启自动就绪、恢复网络、30分钟真实播放混合测试；报告所有未完成项 |

## 回答质量与完成机制

1. 先记录ASR输入、模型全文、finish_reason、生成异常、合成文本与播放片段序号及完成状态。保留现有阶段计时；普通聊天生成状态与工具执行状态分别记录。
2. 用文字直接输入和固定录音各跑一遍问题，隔离识别与生成因素。新会话与有历史会话分别测；检查是否将用户话语误送到回答/合成路径。
3. 对话策略按意图调整：日常闲聊可简短；知识题允许2—4句，先直接回答再解释/举例；操作题给实际步骤；不确定时明确能力边界。回复预算按类型调整并测时延，不统一套用30字/48 token，也不无限增加长度。
4. 禁止无执行链的“我想一想，稍后告诉你”。离线知识问答应当在本轮给出答案或说明不知道。未来若引入异步检索，必须有任务标识、运行状态、超时、最终回执；当前不虚构后台任务。
5. 检测纯复述、仅占位回复和异常截断；长度/相似度只能辅助判定，合理引用、翻译、确认信息应豁免。对明确失败可最多一次有时限的纠正生成；持续失败用明确说明收尾并记录，不无限重试。
6. 流式播报先产出有内容的完整首句；不能只播放“让我想想”就结束或计为两秒达标。已播出的不完整内容无法撤回，需在首段放行前完成最低质量检查，并计入其延迟成本。
7. 若1.7B模型在合理提示与预算下仍不能通过知识/追问集，再比较候选模型与运行硬件。离线小模型的知识能力上限要如实说明；检索、云端模型或电脑代算会改变运行约束，不默认启用。

## 收音与工具

- 当前候选已由真人电平样本更新为−46 dBFS、200ms聊天起音；旧−38 dBFS方案会漏掉该正常语音样本，已否决。下一轮先对照起音与前置缓存，再评估RMS与VAD联合判断；保持实际麦克风增益与距离，不能将dBFS当作声压分贝。详见上方最新优先项与microphone-calibration-2026-11-12.md。
- 目标：正常语音至少19/20次触发；希望忽略的小声最多1/20次误触发；安静5分钟无误回复；保留半秒句中停顿与首字。若声级重叠，调整拾音或唤醒策略。
- 音量工具验证相对调节、百分比、静音恢复、否定与问句不误执行。再测未写入词表的自然表达、中文数字与复合请求；模型只产生受校验的工具请求，不执行任意Shell。
- 工具成功必须依据实际执行结果，不以模型口头承诺判成功；静音响应单列，不算有声首响应。播报中打断属于独立后续任务，当前未实现。
