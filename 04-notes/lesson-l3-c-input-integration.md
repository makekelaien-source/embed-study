## 整行读取契约

沿用 `03-code_codex/shared-command/d12-line-reader.h` 与 `d12-bounded-command.h`。课堂先给正在追踪的真实实现，一次只观察读取状态或结果。缓冲 `char text[16]` 可放最多 15 个正文字符和终止符；输入是无内嵌 NUL 的文本。

| 读取状态 | 产生条件 | 能依赖的数据与调用者动作 |
|---|---|---|
| `LINE_READY (1)` | 得到完整行，包括符合容量的无换行末行 | `text` 是有终止符且去掉行尾换行的字符串。仅此状态调用分类器 |
| `LINE_END (0)` | 本次未读到正文或换行就遇到 EOF | 本轮没有可分类文本，正常结束 |
| `LINE_TOO_LONG (2)` | 当前行超过 15 个正文字符，余量已消费至换行或 EOF | 缓冲可能保留前缀，整行不能分类。报一次诊断，继续读取 |
| `LINE_IO_ERROR (-1)` | 读取或清尾后标准输入的错误标志已置位 | 本轮缓冲不用于分类，报诊断并退出 |
| `LINE_BAD_BUFFER (-2)` | 缓冲是 NULL 或容量小于 2 | 调用参数错误，无可分类字符串，报诊断并退出 |

对照输入：空流第一次得 `LINE_END`；单独的换行先得 `LINE_READY` 且 text 为 `""`。15 个正文字符后接换行可以分类；16 个正文字符后接换行必须跳过整行。输入 `CMD/RUN\nXXXXXXXXXXXXXXXX\nCMD/STOP\n` 时，读取状态依次为 1、2、1、0。分类整数由旧模块原样传递。例中的 RUN 为 1、STOP 为 2，它们是分类结果，和读取状态属于不同接口。

## 新知识：输出流与退出码

`stdout` 与 `stderr` 都是 `<stdio.h>` 提供的输出流。终端可能把两者都显示在同一处，测试工具可分开捕获。正常业务结果写 stdout，诊断写 stderr。

`fputs(text, stream)` 接受有效的 NUL 结尾字符串和可写输出流，写入直到 NUL 前，既不写 NUL，也不自动附加换行。成功返回非负值，写出错返回 EOF。本节先观察正常输出，输出设备失败留作扩展。已有的 `puts(text)` 写 stdout 并附加换行。main 的 `return 0` 表示正常结束；本练习约定用 `return 1` 表示致命错误。退出码由调用者读取，和屏幕打印分开。

```c
#include <stdio.h>

int main(void)
{
    puts("RESULT");
    fputs("READ_ERROR\n", stderr);
    return 1;
}
```

第一行输出调用写 `RESULT\n` 到 stdout，第二行写 `READ_ERROR\n` 到 stderr，最后进程以 1 退出。开课后先让学生预测一项，再展示分开捕获的结果。

## 学生交付与验收

授课到练习时再准备空白目标文件和构建入口。复用现有读取器和分类器，学生只写新的控制台 `main`，保留旧程序。规范：仅 READY 调用分类器，将结果打印到 stdout；过长诊断 `TOO_LONG\n` 写 stderr 并继续；EOF 安静退出 0；读错误写 `READ_ERROR\n`，无效缓冲写 `BUFFER_ERROR\n`，两者退出 1。错误状态由教师支架注入，不要求学生制造系统错误。

| 输入或状态 | stdout | stderr | 退出码 |
|---|---|---|---:|
| RUN、16 个 X 的过长行、STOP，随后 EOF | `1\n2\n` | `TOO_LONG\n` | 0 |
| `CMD/STOP`，末尾无换行 | `2\n` | 空 | 0 |
| 空流 | 空 | 空 | 0 |
| 注入读取错误 | 空 | `READ_ERROR\n` | 1 |
| 注入无效缓冲 | 空 | `BUFFER_ERROR\n` | 1 |

测试设计先明确目标与植入错误。例如，目标遇到 TOO_LONG 后继续读取，植入错误遇到 TOO_LONG 就退出。对照输入必须把有效命令放在坏行后面，并分别写出两个版本的可观察差异。若提前完成，在同一原型补 15/16 字符边界、长行末尾无换行和诊断次数，不跳到下一主题。
