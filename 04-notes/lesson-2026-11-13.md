## 三、新知识：为什么要写uint8_t而不是猜int有多少位

### 1. 问题和类型

当一个字段必须容纳“0至255的标志”或“0至65535的编号”时，明确位宽有助于选择范围与存储；int只保证最低范围，不保证任何机器都32位。

头文件`<stdint.h>`在支持相应精确位宽类型的实现上提供：

| 类型 | 位宽/符号 | 数值范围 |
|---|---|---|
| uint8_t | 无符号8位 | 0至255 |
| uint16_t | 无符号16位 | 0至65535 |
| uint32_t | 无符号32位 | 0至4294967295 |
| int16_t | 有符号16位 | -32768至32767 |

这些精确位宽类型可能因平台能力而不存在；本机例子会编译验证其存在。选择类型要看业务范围，不能为“省空间”悄悄截掉合法温度或编号。日课筛选核心继续复用原Sample，不要求为学类型重写上一日所有源码。

```c
#include <stdint.h>
uint16_t sensor_id = 1000;
```

类型名可像unsigned int一样用于声明；变量不会因为叫sensor_id就自动检查编号契约。`UINT8_MAX`是stdint.h给出的uint8_t最大值常量；不是一个运行时检查函数。

### 2. 算出256与存成0是两个步骤

[完整最小例](next-day-demo/l4-2026-11-13/width-demo.c)：从uint8_t的255开始，计算加1，再转换回uint8_t。

```c
uint8_t byte = UINT8_MAX;
byte = (uint8_t)(byte + 1);
```

在本机，byte参与加法时先整数提升为int，因此`byte+1`的中间值是256；转换回无符号8位得到256模256，即0。不是说所有中间表达式都只按8位算。即使不显式写转换，赋值存回较窄的无符号类型也有相应转换规则。

`(类型名)表达式`是显式类型转换：产生转换后的值，不修改原对象，除非把结果赋回；本例的括号明确先算加法再转换。对有符号溢出不能套用无符号回绕规则；超出有符号目标可表示范围的转换也不能擅自假定所有机器相同。当前只演示合法中间计算与无符号转换。

教师例还用`UINT32_C(1)`构造适合相应无符号宽度运算的常量；再左移12位得到4096，避免把1u在所有机器上都假定为32位。移位次数仍须小于运算类型位宽。教师打印支架把窄无符号类型转成unsigned int配%u、uint32_t转成至少32位的unsigned long配%lu，学生目标核心不要求背这些显示转换。

输出预期`bits=8,16,32 values=0,1000,4096`。这只是本机教师预检结果，不能算学生独立选择类型或编码能力。

理解检查只选一个：若业务编号上限为1000，uint8_t是否够用？要先说明范围理由，再谈代码。

## 四、新知识：结构体数组与只读接口

### 1. 一个数组中每个元素都是完整对象

```c
struct Reading { int id; int value; };
struct Reading readings[] = {{1, 10}, {2, 20}};
```

外层花括号列数组元素，内层每一组按结构体成员顺序初始化一个对象；这里有两个元素。索引从0开始，`readings[1]`是第二个struct对象，`readings[1].value`为20。每个元素包含自己的两个字段，不能把“第几个元素”和“哪个成员”混成同一下标。

```c
struct Reading *p = &readings[1];
p->value = 27;
```

取到第二条记录的地址，修改该记录的value；第一条记录不变。[完整例](next-day-demo/l4-2026-11-13/array-demo.c)输出`first=10 second=27 read=27`。

数组元素之间的间距是sizeof整个结构体，不是一个成员大小；不能跳过填充自行做字节步长。优先让数组索引承担地址计算。

### 2. 数组参数与const

```c
int read_second(const struct Reading readings[], int count);
```

这里数组形参会调整为指向元素的指针，不能在函数内用sizeof readings推出原数组长度。count由调用者提供，合法下标为0至count-1。

const约束通过此接口修改所指元素：`readings[1].value=27`应被编译器拒绝，但读取允许。它不保证原数组在别处永远不变。`const struct Reading *p`限制所指对象的这条访问路径，不等于p这个局部指针本身不能改指向。

当前目标数组长度保证非负，count0时允许指针NULL并且不能访问任何元素。count大于0时，调用者保证至少有count个有效对象。本题不要求猜测任意地址是否有效。

## 五、新知识：多个位“任一满足”和“全部满足”

一个掩码不一定只含一个1。mask=3，二进制011，同时选中风扇和报警器。业务可以有两个不同查询：

- ANY：两个选中设备里，至少有一个开着就匹配。
- ALL：两个选中设备必须全部开着才匹配。

先算选中部分`flags & mask`，再根据查询语义判断：

```c
(flags & mask) != 0      /* ANY：至少一位为1 */
(flags & mask) == mask   /* ALL：每个选中位都为1 */
```

括号不能省略成`flags & mask == mask`：比较运算比按位与结合得更紧，会改变计算分组。按位结果是整数，比较结果才是0或1。

| flags低三位 | mask | 取出部分 | ANY | ALL |
|---|---|---|---:|---:|
| 001（1） | 011（3） | 001（1） | 1 | 0 |
| 011（3） | 011（3） | 011（3） | 1 | 1 |
| 100（4） | 011（3） | 000（0） | 0 | 0 |

[完整例](next-day-demo/l4-2026-11-13/multi-mask-demo.c)先检查1，再检查3，输出`partial=1,0`和`complete=1,1`。

mask=0时ANY恒假、ALL恒真，是空选择的数学后果；为避免本题业务歧义，下面两个筛选模式都保证mask在1至7内。不能临时用“0表示错误”改变既定计数返回语义。

### K4：只读筛选计数

核心文件`count-flagged.c`：

```c
int count_flagged(const struct Sample samples[], int count,
                  unsigned int mask, enum FlagMatch match);
```

| 输入/返回 | 契约 |
|---|---|
| samples与count | count>=0；count>0保证足够有效对象，count0可NULL |
| mask | 只传1至7，指定至少一个低三位设备 |
| MATCH_ANY（0） | 至少一个选中设备开启即计入 |
| MATCH_ALL（1） | 所有选中设备开启才计入 |
| 返回值 | 0至count的匹配条数；0是没有匹配项或空数组，不是失败 |
| 数据保持 | 所有Sample成员都只读、不变；函数不打印 |

状态match是查询方式的选择参数，不是每条记录的等级；level仍是温度分类，flags仍是设备状态，两者不替代。调用者保证match只为上述两个常量。每条记录最多计一次；即使两个目标位都开着，也不是计两次。

基准数组四条记录flags依次为1、3、4、0，其他字段已合法初始化：

| count | mask | match | 返回 |
|---:|---:|---|---:|
| 4 | 3 | ANY | 2 |
| 4 | 3 | ALL | 1 |
| 4 | 4 | ANY | 1 |
| 4 | 7 | ALL | 0 |
| 0（NULL） | 3 | ANY或ALL | 0 |

单元素、末元素命中、全不命中、输入所有成员保持由教师批跑。学生设计核心遍历和判定；教师不预填目标循环或完整实现。

### K5：批量更新选中设备

核心文件`sample-set-batch.c`：

```c
void sample_set_batch(struct Sample samples[], int count,
                      int bit, int enabled);
```

count/有效数组契约同上，bit只0至2、enabled只0/1；返回void，无状态码。对每条记录只改变flags中指定设备位，其他位及sensor_id、temperature、level必须保持。count0可NULL，什么也不访问。学生复用已有set_switch_at，不复写置位/清位核心；已有函数源码教师提供链接。

对flags为1、3、4、0的四条记录：先开第2位→5、7、4、4，再关第1位→5、5、4、4。重复同样操作应保持结果；不同记录不互相复制覆盖。中间状态可由显示/筛选读取，体现同一数组供多个功能复用。
