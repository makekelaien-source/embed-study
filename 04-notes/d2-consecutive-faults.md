# D2新应用：连续故障与历史最长纪录

## 目标、前置与时段

C主线，计划45–60分钟包含需求/新状态解释、学生实现、教师批测、学生修正/根因说明；真实完成快则按证据进阶，不假填计划。前置为计数、最大值、if/else、数组遍历、宏、可选标量is_fault函数；新点是当前连续状态和历史最长状态的不同更新时机。

## 先说明业务含义

- 只有-999是故障，其他整数（含0、其他负数）均正常。
- 连续故障必须相邻，正常值会分隔故障段。
- 当前连续数描述“到目前这个位置为止，末尾连续故障有几个”；正常值将它清零。
- 历史最长描述“扫描过的所有故障段，最长达到几个”；正常值不清除纪录。
- 示例{-999,-999,23,-999}共3次故障，但最长连续2，最终当前连续1。状态表依次(1,1)/(2,2)/(0,2)/(1,2)。

先讲清两个状态再发完整任务，学生不需逐行回答初始化等已教基础问题。教师短例next-day-demo/d2-streak-state-demo.c只演示已累积2后遇正常再遇故障的局部转移，不给数组扫描目标核心。

## 学生完整任务

文件03-code_codex/d2-consecutive-faults.c由助手先建空白。

定义SAMPLE_COUNT为8，样本{-999,-999,23,-999,-999,-999,24,-999}。找最长连续故障段的长度，最后输出两行：第一行最长连续故障数；第二行若最长>=3打印“报警”，否则“正常”。原数组预期3/报警。阈值是本题软件练习规则，并非已验证的硬件安全策略。

可参考旧最大值/故障计数代码或沿用is_fault，但核心由学生写，不提供完整扫描循环。无需输入或指针。

## 教师验收（临时副本，保留原作）

| 数据 | 最长/状态 |
|---|---|
| 原8样本 | 3/报警 |
| 全正常8项 | 0/正常 |
| 全故障8项 | 8/报警 |
| -999,-999,1,-999,-999,2,3,4 | 2/正常 |
| 1,2,3,4,5,-999,-999,-999 | 3/报警 |
| -999,-999,-999,1,-999,-999,2,3 | 3/报警 |
| 1,2,3,4,5,6,7,-999 | 1/正常 |

不只在遇正常时更新最大值，否则末尾连续段可能漏算；不把所有故障总数当连续数。定位每轮1–2个根因再学生改。通过后解释一个真实失败用例；若首稿通过则说明与总故障计数差别即可，不用简单重复口问。约11-04新情境复测待做。
