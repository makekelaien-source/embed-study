## 四、新知识：通过指针访问结构体成员

### 1. 解决什么问题

把结构体按值传给函数，函数拿到一个对象副本；修改这个副本不会改调用者的整数成员。如果要求更新调用者的记录，可以传入那条记录的地址。

```c
struct Reading { int id; int value; };
struct Reading a = {7, 25};
struct Reading *p = &a;
```

`p`是指向struct Reading对象的指针，保存a的地址。`a.value`用对象取成员；`(*p).value`先找到所指对象再取成员。C提供等价简写：

```c
p->value = 26;  /* 等价于 (*p).value = 26; */
```

规则：左边p必须指向仍然存在且类型匹配的有效对象，`->`不会创建对象；NULL和已失效地址不能解引用。`p->value`可读也可写，取成员本身不改变p的指向。`*p.value`不能替代`(*p).value`，因为`.`先结合，会被解释为`*(p.value)`。

### 2. 最小示例和执行过程

[完整示例](next-day-demo/l4-2026-11-12/pointer-demo.c)：

```c
void increase(struct Reading *p) {
    p->value += 1;
}
```

教师入口先创建`a={7,25}`，再用a整体初始化快照b；令p指向a，调用increase(p)。函数形参收到指针值的副本，两份指针指向同一个a，因此a.value变26，b仍25。返回后形参p的本次自动对象寿命结束，main里的a仍存在。本例不引入函数声明前static的另一种用法，避免把文件作用域链接规则混入局部存储期。

预期输出：

```text
a=7,26 b=7,25
```

课堂只出一个预测：改为让p指向b，再调用一次，哪个对象变？教师答案独立保存在teacher-guides中，学生未答前不直接呈现。

### 3. 按值与按指针对照

[完整对照例](next-day-demo/l4-2026-11-12/copy-demo.c)逐条调用，避免把多次有状态调用塞进一个printf参数列表。

```c
void by_value(struct Reading r) { r.value = 99; /* 显示内部副本 */ }
void by_pointer(struct Reading *p) { p->value = 99; }
```

从a.value=25开始，by_value(a)内部可看到99，但返回后a仍25；by_pointer(&a)后a为99。C始终是值传递：传指针时复制地址值，不是语言切换成“引用传递”。

## 五、学生新核心与状态契约

教师已创建`D:/Apostgraduate/opencode/embed-study/03-code_codex/l4-2026-11-12/`。头文件sample.h和sample-main.c由教师准备；两个核心文件为空白，课堂开始前再次检查，已有作答一律保留。

头文件定义：

```c
enum HeatLevel { HEAT_LOW = 0, HEAT_NORMAL = 1, HEAT_HIGH = 2 };
struct Sample {
    int sensor_id;
    int temperature;
    enum HeatLevel level;
    unsigned int flags;
};
```

这不是新的状态机章节，而是L4“样本与标志位模块”：level保存同一条记录的分级，显示端与报警端共用这个结果，无需各自重算温度。

### K2：只更新温度成员

文件：`D:/Apostgraduate/opencode/embed-study/03-code_codex/l4-2026-11-12/sample-set-value.c`。

```c
void sample_set_value(struct Sample *sample, int temperature);
```

源文件包含`"sample.h"`。sample保证指向有效可写对象；temperature是任意合法int，本题不做输入解析或非法指针恢复。返回void，无返回状态。只更新temperature，sensor_id、level和flags保持。即便旧level暂时与新温度不一致，也由下一步刷新负责，这个短暂状态在题面明确允许，调用者不能在刷新前把旧level当成新温度等级。

验收：`{7,25,HEAT_NORMAL,5}`传入30后为`{7,30,HEAT_NORMAL,5}`；先前值快照不变。温度-1合法，不是EOF。输入保证有效不等于可把温度和EOF比较。

### K3：刷新等级与报警位

文件：`D:/Apostgraduate/opencode/embed-study/03-code_codex/l4-2026-11-12/sample-refresh.c`。

```c
void sample_refresh(struct Sample *sample);
```

同样保证有效可写对象、返回void。只更新level与flags的第1位（报警器）；sensor_id、temperature及flags其他所有位保持。使用刚完成的set_switch_at更新该位，学生不重写位运算函数。分类规则：

| level常量 | 数值 | 产生条件 | 报警器第1位 | 可依赖数据 |
|---|---:|---|---|---|
| HEAT_LOW | 0 | temperature<20 | 0 | 原id/温度、更新后level/flags均有效 |
| HEAT_NORMAL | 1 | 20<=temperature<30 | 0 | 同上 |
| HEAT_HIGH | 2 | temperature>=30 | 1 | 同上 |

每次刷新都重建一致的level与报警位，不依赖此前level或报警位是否正确。风扇第0位、照明第2位及高位不受影响。

| 原id/温度/level/flags | 刷新后level/flags | 覆盖目的 |
|---|---|---|
| 7 / 30 / LOW / 5 | HIGH / 7 | 高温设置报警，保留风扇照明 |
| 8 / 19 / HIGH / 7 | LOW / 5 | 降温清报警，不清其他设备 |
| 9 / 20 / LOW / 133 | NORMAL / 133 | 下边界与高位保留 |
| 9 / 29 / LOW / 133 | NORMAL / 133 | 上边界前 |
| 9 / 30 / LOW / 133 | HIGH / 135 | 含第7位的原状态仍保持 |

两条记录分别更新，不能把字段保存进单份函数static中；否则多个对象会共享错误的实例状态。这是本日与静态计数器的真实设计区别。

## 六、布局基础：成员齐全不代表没有空隙

`sizeof`返回对象/类型占用的字节数，类型为size_t；打印它用`%zu`。不把字节数直接当位数。机器可能为int等成员设置对齐要求，在成员之间或结构体末尾加填充；因此不能普遍假定sizeof结构体等于各成员sizeof之和。

[布局示例](next-day-demo/l4-2026-11-12/layout-demo.c)使用：

- `sizeof(struct Layout)`：整个类型的大小，单位字节。
- `_Alignof(struct Layout)`：C11类型对齐要求，单位字节，参数是类型名。
- `offsetof(struct Layout, value)`：来自stddef.h的宏，给出成员value相对对象起点的字节偏移，不是成员大小；这里用于普通非位域成员。

对`char tag; int value; char tail;`观察大小、对齐和三个偏移。输出是本机证据，不规定所有机器必须相同。不读取未初始化字段，不用原始内存写文件冒充可移植序列化。
