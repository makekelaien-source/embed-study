# 笔记 01：一个 C 程序的「施工图」结构

> 对应文件：`03-code\hello.c`。把程序想象成一套施工图，每个部分各有分工。

## 骨架（每个 C 程序都长这样）

```c
// 这是注释，编译器不看，写给人看的

#include <stdio.h>        // ① 材料单：告诉编译器我要用"输入输出"这套现成工具

int main(void)            // ② 施工起点：程序永远从 main 开始执行
{
    printf("Hello!\n");   // ③ 一道工序：调用 printf 往屏幕打印一句话
    return 0;             // ④ 收工：告诉系统"正常结束"
}
```

## 逐块解释

| 部分 | 类比 | 作用 |
|---|---|---|
| `#include <stdio.h>` | 材料单 | stdio = **std**in/**o**ut**p**ut（输入输出库）。要用 printf，就得先声明"我要用这套工具" |
| `int main(void)` | 大门/起点 | 一个 .c 文件里必须有且只有一个 main，程序从这里进场 |
| `{ }` | 围墙 | main 的所有工序写在围墙里面 |
| `printf("...")` | 一道工序 | 括号里是要打印的内容，文字必须用英文双引号包住 |
| `\n` | 回车键 | 打印完换行。`\` 开头的都是"特殊指令"（转义字符） |
| `;` | 工序之间的分隔线 | **每条工序结尾必须有分号**，少了它编译器就看不懂 |
| `return 0;` | 验收报告 | 0 = 一切正常 |

## 三条铁律（已踩过坑）

1. 代码里的标点全部用**英文**：`( ) " ; ,` 不能是 `（ ） “ ； ，`
2. 报错读法：`hello.c:4:62: error: 说明` = 第 4 行第 62 列，**先修第一个错**，后面的可能是连锁反应
3. 编译失败时 exe **不会更新**，跑的还是旧版——所以 go.bat 里编译失败就不运行

## 编译运行（三行命令）

```powershell
cd D:\Apostgraduate\opencode\embed-study\03-code      # 进入代码目录
gcc -Wall -o hello.exe hello.c # 编译（成功时沉默无输出）
.\hello.exe                    # 运行
```

快捷方式：`.\go hello`（go.bat 一条命令搞定后两行）

注意：PowerShell 不运行当前目录下的程序，必须加 `.\` 前缀（`.\go`、`.\hello.exe`）。cmd 里则不用。
