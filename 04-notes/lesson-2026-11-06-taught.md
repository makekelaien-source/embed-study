# D10 实授讲义：整行输入、状态和分编译链接

课堂处于 L2 时间窗口，提前进入 L3 文本输入与声明、头文件。本文收录已讲机制，提示、实测及学生原稿见学习册相应章节。课堂中用临时目录验证的对照在下方给出可复现的规则与输入。

## 读操作、缓冲区和行尾

`fgets(text, capacity, stdin)` 最多从流中消费 `capacity - 1` 个字符。先遇到 `\n` 就把换行也存进数组并停止。成功时补写 `\0` 并返回 `text` 的地址。没有读到任何字符就正常结束，或读取失败时，返回 `NULL`。检查返回值后再访问数组。`fgetc(stdin)` 每次尝试读一个字符，成功返回字符的 `int` 值，读到换行就返回 `'\n'`。没有拿到字符时返回 `EOF`，应使用 `int` 接收。读输入会推进流的位置，检查数组和流标志只观察现有数据。

容量 8，已成功调用一次 `fgets` 时：

| 流原输入 | 数组前部 | 流当前位置 |
|---|---|---|
| `ABC\nOK\n` | `A B C \n \0` | `OK\n` |
| `ABCDEFG\nOK\n` | `A B C D E F G \0` | `\nOK\n` |
| `ABCDEFGHI\nOK\n` | `A B C D E F G \0` | `HI\nOK\n` |

数组里已经有换行时，流中第一行已经结束。数组无换行时补读一个字符，得到换行代表正文恰满，得到额外正文代表仍有本行内容，读到 `EOF` 要区分正常结束和读取错误。`read_text` 把换行改写成 `\0` 是自己的赋值操作。`sizeof text` 对实际数组表示容量，对指针形参表示指针大小。`sizeof stdin` 同样只表示 `FILE *` 指针的大小。要数一行原始正文长度，累计实际读到的正文字符，直到换行或 `EOF`。换行被消费，但可按任务约定排除在正文长度之外。

短路求值按顺序发生。`f() == a || f() == b` 在左侧为假时会执行第二次 `f()`。若 `f()` 消费输入，第二次会从新位置开始。先写 `int result = f();` 再两次比较 `result`，两次比较就共用一个返回值。超长第一行清掉行尾之后再错误调用一次，会消费原本留给下一行的字符。

## EOF、流标志和调用者策略

流的结束和错误标志记录已经发生的状态。`feof(stdin)` 非零说明已观察到结束，`ferror(stdin)` 非零说明流上记录了读写错误。非零的具体数值不是下标。`feof != 0` 比较的是函数地址，`feof(stdin) != 0` 才执行查询。期待数字却读到 `2A`，是数据格式不合要求，字符仍可以成功读取。只写流上尝试读字符是教师实测过的读取错误对照。

文件中只有 `A` 时，第一次 `fgetc` 返回 `'A'`，结束标志为零，再读一次才返回 `EOF` 并设置结束标志。`fgets` 读无换行的 `MODE` 时，已有四个字符可交付，可能同时确认结束，所以必须先处理成功读取的数据。文件只有 `MODE\n` 时，第一读成功且无结束标志，第二读返回 `NULL`、结束标志非零、错误标志为零。若第二次失败且错误标志已设置，就不能认作正常缺行。

`classify_read` 接收一次 `fgetc` 的结果和两个标志。字符、正常结束、读取错误、无标志兜底分别为 1、0、-1、-2。同为非零时错误优先。课堂教师把 8 和 4 用作非零标志的测试值。

`command_is_usable` 接收读取层状态、可用文本与是否确认正常结束。已确认换行的完整行只检查非空。未确认行尾但有正文时，需同时确认是正常 EOF 且非空。其余状态直接拒绝，允许 `text` 为 `NULL`。空串可在字符串有效的前提下用 `text[0] == '\0'` 判断。实现中 `return` 提前结束路径，两次不同状态检查应保证所有路径返回。课堂先用人工状态测试纯策略，再由教师支架接真实标准输入。完整多行入口的独立实现留到 L3 后段。

## 分编译、链接和实操

头文件提供函数声明，调用方和实现方使用同一签名。`gcc -c main.c -o main.o` 到目标文件为止；`gcc -c add-one.c -o add-one.o` 生成实现目标。仅 `gcc main.o -o demo.exe` 实测 `undefined reference to add_one`，因为调用目标中尚有需要解析的引用。把两个目标文件交给 `gcc main.o add-one.o -o demo.exe`，用户实测运行输出 `6`。`demo.exe` 是这一步的输出。只修改 `add-one.c` 的函数体时，需要重新生成 `add-one.o`，再和原 `main.o` 链接。教师临时副本验证重新链接旧目标仍输出 `6`，更新实现目标后输出 `7`。

## 计数、选例与课内迁移

- 第一行是 `ABCDEFGHI\n`、容量 8 时，`fgets` 取走 7 个字符，行尾清理取走 `HI\n` 共 3 个，合计 10。数组找换行或结束符时访问下标 0～7 共 8 个位置，补写的结束符属于数组访问。
- 学生选中 `ABCDEFG\n` 作为区分恰满和超长误判的输入。教师正确版本输出 `ACCEPT ABCDEFG`，故意把满容量直接认定超长的版本输出 `REJECT TOO_LONG`。两者初读得到同样数组，区别在是否去看下一个流字符。
- 短检验用 `RUN\nON\n` 和 `RESTART\nON\n` 对照一次无条件补读。学生能预测先吃掉 `O` 或换行，对应第二次 `fgets` 得到 `N\n` 或 `ON\n`。Python 文字检验用 `show.py` 导入 `sensor.py`，模块顶层输出 `LOADED`，入口保护跳过 `DIRECT`，显式调用后输出 `8`，学生预测正确。
- 自选长行清理：先验证 `fgets` 的返回值，扫描已存字符串查找换行。第一行的换行若已消费，下一字符才是第二行首字母。若还没有消费，补读到换行或 `EOF`。清行后在 `\n` 的路径再取第二行首字母，遇到 `EOF` 直接处理缺行。避免在扫描数组的第一个非换行字符处就进入清行，也避免把清行返回的换行当首字母比较。

## 高频易错点与复测

| 误区 | 正确规则与证据 | 待复测 |
|---|---|---|
| 容量、原始长度和换行混用 | 六字母加换行与结束符需八格；恰满且未存换行要看后继字符。最终自选稿的教师九组输入已验。 | 约 11-13 的短变式 |
| 只在第一次读后判 `EOF` | 后续清行和取第二行都可能遇到 `EOF`；该分支修正后补测通过。 | 与上项合并 |
| `fgets` 数组地址和返回值混用 | 数组地址存在并不能证明本次读成功，用 `fgets(...) == NULL` 判断；`fgetc` 使用 `int` 和 `EOF`。 | 一道返回契约迁移 |
| 只改源文件后链接旧目标或把 exe 当输入 | 源文件改动需编译为新目标，链接输入是目标文件。学生实操成功，周检中选对重编译源文件但链接输入有误。 | 约 11-13 诊断 |
| 内容不合法等同读取错误 | 内容判断在读成功后做，流错误标志只反映读写故障。 | 后续与异常路径合并 |
