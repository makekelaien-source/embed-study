## 首讲与短例

门口的灯只有灭 OFF 和亮 ON 两种持续状态。命令 PRESS 表示按了一次按钮，WAIT 表示这一拍无操作。事件是这一次发生的事；状态是下一次事件到来时还要用到的信息。相同的 PRESS，在 OFF 时到 ON，在 ON 时到 OFF；WAIT 保持当前值。把“旧状态、一个事件”交给函数，函数返回此次处理后的状态；枚举按值传入，调用者把返回值写回自己的状态变量。一次调用消耗一个事件，序列处理到最后一个事件就停止。这里每次收到的已经是一个抽象事件，无需轮询、消抖或操作硬件。

教师短例见 next-day-demo/D20-state-demo.c，先读默认分支并预测，再运行。初始打印 OFF。第一次 PRESS 后写回 ON，WAIT 后仍为 ON，最后 PRESS 后写回 OFF。输出 OFF ON ON OFF。若调用者丢弃返回值，下一拍仍会从旧值计算。理解检查只问一项：相同起点，第二个命令从 WAIT 改成 PRESS，第二次调用返回什么？

## 本题的设备契约

应用情境为桌面采集程序。应用启动时状态为 BOOT。每次调用只处理一个列出的事件，返回值描述处理完这一拍后的状态，调用者可继续传入它；函数不读写硬件。没有附加标志或输出数据。输入均为头文件所列的有效枚举值。

| 状态 | 含义、产生条件及可依赖的行为 |
|---|---|
| BOOT | 上电进入，或 SAFE 收到 RESET 后进入；等待重新自检，START 此时不能开始采集 |
| IDLE | BOOT 自检完成收到 READY，或 RUN 收到 STOP 后进入；现在允许 START |
| RUN | IDLE 接受 START 后进入；表示程序获准采集，本题不产生真实采样值 |
| SAFE | 任意状态收到 FAULT 后进入；锁住启动，只有 RESET 可回 BOOT，恢复后仍须重新 READY |

READY 表示本次自检通过；START 表示一次开始请求；STOP 表示一次停止请求；FAULT 表示一次故障报告；RESET 表示一次人工清除故障请求。只有 SAFE 接受 RESET。所有状态都接受 FAULT，其余没有明确动作的组合均保持原状态。输入无优先级冲突，因为单次只有一个事件。例如 BOOT+START 保持 BOOT，IDLE+START 返回 RUN；SAFE+READY 保持 SAFE，BOOT+READY 返回 IDLE。
