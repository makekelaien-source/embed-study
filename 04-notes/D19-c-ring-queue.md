## 槽位留下，读写位置移动

三个槽位保存尚待处理的编号。先放入 10、20，再取一个，取出 10；之后到达的编号排在 20 后面。这种“先到先取”的规则叫 FIFO。固定数组占用三个槽位；处理最前面的编号以后，可以让后面的写操作重新利用空出的槽位。

本题 head 指向下一个待读槽，tail 指向下一个待写槽，count 是尚未取出的数量。三个值都在结构体里，每个队列有自己的状态。用 struct IntQueue q = {0}; 初始化，所有字段从零开始。合法下标为 0、1、2，count 范围为 0 到 3。count 为零时没有可读槽；count 为 3 时没有可写槽。即使打印出旧值，也只有占用范围内的槽才表示待处理数据。

C 的 % 运算对这里的非负整数给出除法余数。下标加一后对正容量取余，可把前进的位置重新映射进合法区间。教师例从 1 开始，先打印当前下标，再计算下一个。1 的后继是 2，2 的后继是 0，随后又到 1。预测时只画三个格子，区分“刚访问哪个槽”和“下次访问哪个槽”。容量为零时不能取余；本题容量固定为 3。

若只插入 10，起初 head=0、tail=0、count=0。成功后槽 0 有 10，head=0、tail=1、count=1。接着取一次，输出 10，head=1、tail=1、count=0。下一次空队列读取不产生编号。理解检查：若连续三次插入均成功，此时两个位置是否可能相等？选择一个字段判断是否还可以插入。由学生在纸上走完再编程。

## 学生核心与状态契约

头文件及两项接口由教师提供。练习开始时只在已经准备的空文件 D:/Apostgraduate/opencode/embed-study/03-code_codex/D19-ring-queue.c 中写入两个核心，包含 "D19-ring-queue.h"。接口如下。

~~~c
enum QueueResult queue_push(struct IntQueue *q, int value);
enum QueueResult queue_pop(struct IntQueue *q, int *out);
~~~

q 必须指向已初始化且满足上述状态范围的对象。value 可以是任意 int，0 与负数都是合法编号值。出队的 out 指向可写 int，不与队列重叠。返回枚举值描述这一次操作的结果，调用者用名字判断。本题不接收 NULL 参数。输入超出此契约时无需设计额外的状态。

| 返回状态 | 产生条件 | 此后可以依赖的数据 |
|---|---|---|
| QUEUE_OK | 入队时有空位，或出队时有待取项 | 入队后新值位于队尾，旧值的逻辑次序保持。出队后 *out 为最老的一项，只消耗这一项。 |
| QUEUE_FULL | 满队列请求入队 | 队列所有字段和槽值保持，新输入未存入；之后仍能依次取出原来的各项。 |
| QUEUE_EMPTY | 空队列请求出队 | 所有字段和槽值保持，*out 也保留调用前的值，本次没有可交付的数据。 |

例：把 out 初始化为 -99，空队列出队后仍为 -99；成功取出一个值为 -99 的元素时数值看起来一样，操作结果由返回状态区分。成功出队后旧槽可以保留原值，取出顺序只由有效范围决定。队列所需空间与容量有关，本题单次入队/出队无需移动其余元素。

组合验收取容量 3。空队列取一次；依次入 10、20、30；再入 40 应提示满且原状态保持；取出 10 后重新入 40；随后三次应为 20、30、40；再取应为空且输出仍为 40。第二个队列可以独立接收并取出 0。GDB 观察只在下标合法时读取 slots，优先选择首次状态变化与预期不一致的操作，比较调用前后的 head、tail、count 及本次输出。
