## 新知识：fprintf 的最小例

`fprintf(stream, format, ...)` 把格式化内容写到指定输出流。第一个参数选流，第二个参数是格式串，后面的值按占位符的顺序取用。示例里的 `%d` 需要 `int`；函数不会自动补换行。正常返回已写字符数，输出或编码出错时返回负值。这里先观察输出成功路径。

示例 `next-day-demo/l3-command/diagnostic.c`。先用 `puts` 向 stdout 写 READY，再将行号 3 填到 %d，向 stderr 写 `line 3: BAD_COMMAND\n`，最后退出 0。PowerShell 5.1 可能给 stderr 加 NativeCommandError 展示信息，验收时区分程序文本、Shell 包装与退出码。

## 学生任务与验收

输入为 ASCII 文本，每行正文最多 14 个字符，无内嵌 NUL，无读取错误；容量 16，可一次容纳正文、换行和 NUL。最后一行允许无换行。学生自行写入口，授课到编程时再创建空白文件。比较命令前去掉实际存在的行尾换行。

- RUN：合法，向 stdout 写 `RUN_OK\n`，继续读取。
- STOP：合法，向 stdout 写 `STOP_OK\n`，继续读取。STOP 在此是业务命令。
- 其他内容，包括空行：业务拒绝，向 stderr 写 `line N: BAD_COMMAND\n`，N 从 1 起算，每成功读一行递增一次。继续读取。
- 读到 EOF：不产生新结果，退出 0。完全空流没有行；单独一个换行是第一行空命令。

| 输入 | stdout | stderr | 退出 |
|---|---|---|---:|
| RUN、BAD、STOP 三行 | RUN_OK、STOP_OK | line 2: BAD_COMMAND | 0 |
| 空行，随后无换行的 RUN | RUN_OK | line 1: BAD_COMMAND | 0 |
| 完全空流 | 空 | 空 | 0 |

设计对照时写出具体植入点：正确版拒绝坏命令后继续；错误版同样写诊断，随即 return 0。使用坏命令后接 STOP 的用例，比较 stdout 是否还有 STOP_OK。提前完成后才考虑加入 D14 的超长恢复能力，学生不用重抄旧函数；允许教师在取得学生对旧模块契约的理解后准备接入支架。计划中的多模块集成继续保留。
