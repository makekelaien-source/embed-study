# 多通道实时采集与故障安全控制终端

> 状态：仅建立需求与学习任务，尚未实现、上电或验收。目标是用可复现证据展示嵌入式软件能力，不将计划当既有成绩。

## 用途与版本

持续采集模拟量和环境数据，接受电脑配置，驱动两个低功率输出，记录事件；通信或传感器故障时进入预定义安全状态。建筑环境可作演示场景，项目重点是数据通路、时序、接口、故障和测量。

## 行为与故障定义

- 启动、复位和未运行时两个PWM默认0%（LED关闭）。状态为BOOT → IDLE → RUN；SAFE为故障后停输出。状态转换表由学生在W5起实现，按这里的行为验收。
- 上位机控制会话运行时，收到有效控制命令或明确心跳刷新存活时间；建议心跳周期200ms。非法帧、普通遥测输出不刷新。最后一次有效存活消息后500ms内输出归零并进入SAFE；实际延迟用外部时序或可核对时间戳测量。
- SAFE后链路恢复不自动启动；故障条件消失后由明确清故障/停止复位状态，再显式启动。失联、传感器异常分别有原因码，不因坏帧误清故障。
- 传感器驱动按数据手册的转换/通信时间给出有界等待；连续3次采集失败确认断连，进入SAFE并上报，低频有界重试。W15冻结具体周期/超时并在测试报告写明；恢复后仍需显式启动。
- 各PWM可独立调占空比，演示默认20kHz；采样与遥测解耦，两个模拟通道最终各1kHz。原始采集计数不等于所有样本都经UART实时发送，遥测可降采样，协议文档说明。
- 接收/日志队列满有计数和可观测错误，不覆盖未消费数据或无限阻塞采集路径。正常吞吐目标下溢出应为0；超负载测试允许按已定义策略拒绝并计数。
- 参数校验/版本失败用默认配置，记录回退原因；重启不恢复RUN。日志写失败要上报，错误路径不得饿死控制/看门狗。
- 看门狗由健康判定喂养，不能每个任务各自随意喂；注入停滞后复位并记录原因。故障注入的预期复位与稳定性测试意外复位分开。
- 本项目的“故障安全”是低功率软件演示行为，不声称工业功能安全认证或硬件级保护。

## 软件接口与数据流

PC核心以显式容量/长度、状态/错误返回值和清晰所有权设计；统计模块定义空输入，环形缓冲区定义满空和回绕，解析器能增量接收，状态机可注入时间。初期先按课堂选定的接口实现并写头文件，不替学生写核心答案。

推荐模块边界：硬件驱动/BSP → 采集与样本缓冲 → 控制状态机；通信解析把命令送控制，控制回ACK/状态，日志消费事件。纯C核心不依赖HAL/RTOS，可在PC和Linux测试；应用层不直接随处操作外设寄存器。

- 裸机使用事件/非阻塞调度，RTOS按采集、控制、通信、日志职责划分任务；ISR只做必要状态/数据交接。
- 明确DMA缓冲区何时可读/重用，队列传值还是传指针、谁释放、满时怎么办；选择写入架构说明。
- W11先文本命令验证；W16冻结二进制协议v1：边界、长度、类型、序号、校验、ACK/错误、超时、最大帧长度及数据单位都需文档和PC测试一致。不假定二进制协议已实现或与早期文本兼容；版本切换明确标记。
- Python工具提供配置/心跳、CSV采集、画图、故障输入和测试报告；命令行优先，不增加复杂界面。
- Cube生成代码与手写模块分离；保存工程配置、工具版本、构建/烧录说明及必要第三方来源。核心路径优先静态分配，不在ISR动态分配。
- 最终目录按core/firmware/host/tests/docs组织；学习阶段只按需要创建，不预先堆空实现。
